# #2 モジュール仕様からの引継ぎ事項の処置表

版: 0.1 / 2026-11-14。本書は [decisions.md](decisions.md) の **OPEN-009(#2 の設計仮定の見直し)を補う処置表**である。OPEN-009 は「実装後の試聴・測定で個別に見直す」とだけ定めており、#2 が #3 へ送った個々の事項をどう扱ったかが追えなかった。本書は [open-issues.md](../specifications/modules/open-issues.md)(各モジュール仕様 §11 の集約)の**全項目**について、#3 でどう処置したかを1行ずつ記録する。

本書は判断を新しく作らない。#3 の文書(製品仕様、操作契約、データ契約、検証計画、判断記録、実装計画)を検索して見つかった処置先を書き、**見つからなかったものは「未処置」と書く**。未処置の項目をどうするかは、オーナーまたは TASK-1016(初期案で実装した事項の見直し)で決める。

## 1. 読み方
- **番号**: 仕様IDと、open-issues.md のその仕様の節での箇条書きの順番(#1 から)。
- **#3**: open-issues.md の原文に「#3」と書かれている項目に ○。
- **処置**の種類:
  | 種類 | 意味 |
  |---|---|
  | 対応済み | #3 の文書に決定または定義がある。参照先(文書・節・ID)を書く |
  | 未決=OPEN-… | [decisions.md](decisions.md) の未決事項として扱われている。個別の OPEN があるものはその ID |
  | 未決=OPEN-009(包括) | 個別の記載はないが、[A](設計仮定)の値・閾値・時間定義・既定値・範囲・式の見直しとして OPEN-009 に含まれる。**現行仕様どおりに実装**し(実装計画 M2)、実装後に TASK-1016 で見直す |
  | 後続 | #2 自身が範囲外・保留・後続とした機能。初期版では作らない。#3 に記載があればその参照先([製品仕様](../specifications/synthesizer/product-spec.md) §6、[要求](../specifications/synthesizer/requirements.md) の REQ-X、decisions.md §4) |
  | #2改訂タスク=TASK-… | [実装計画](implementation-plan.md) の MS(#2 仕様の改訂)のタスクで扱う |
  | 処置不要 | 出所や担当の注記で、判断を求めていない |
  | **未処置** | #3 の判断を求めているが、#3 の文書に処置先が見つからない。1つの項目の一部だけが未処置の場合は、その部分を太字で示す |
- 「OPEN-009(包括)」と「未処置」の分け方: 原文が[A](設計仮定)の値の見直しを述べているだけなら前者。モードや機能の追加、共通規約の変更、製品としての既定動作の選択、UI・伝送の決め方など、**値の見直しを超える判断**を #3 に求めているのに記載がないものは後者とした。
- 参照先の ID: `DEC-`/`OPEN-` は decisions.md、`CMD-`/`EVT-`/`AX-` と「操作契約 §n」は [operation-contract.md](../specifications/synthesizer/operation-contract.md)、`DAT-` は [data-contract.md](../specifications/synthesizer/data-contract.md)、`VER-`/`VP-D` は [verification-plan.md](../specifications/synthesizer/verification-plan.md)、`TASK-` は implementation-plan.md。
