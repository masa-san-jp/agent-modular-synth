## 2. 設計上の決定(通常の選択。理由付き。#3で見直し可)
| ID | 論点 | 決定 | 理由(根拠) | 代替と再検討の条件 |
|---|---|---|---|---|
| DEC-101 | 音声処理の基盤 | ブラウザの **Web Audio API + AudioWorklet**。エンジン全体を1つのAudioWorkletProcessor内で動かす | DEC-001(ブラウザで動く)。AudioWorkletは描画スレッドで低遅延処理でき、MessagePortで制御側と通信できる(F-021-002, F-021-013, F-021-015)。ScriptProcessorNodeは非推奨(F-021-017)。#2のCOM-05/06(1サンプル同期・ケーブル1サンプル遅延)はネイティブのAudioNodeグラフでは表現できないため、単一プロセッサ内で自前のグラフを回す | Web Audioの標準ノードでの構成 → COM-06を満たせない |
| DEC-102 | 実装言語 | **TypeScript**(UI・サーバー・エンジン共通)。DSPも初期はTypeScriptで書き、性能が不足した場合にWebAssemblyへ移す | 1言語で検証コードと実装を共有できる。性能目標は未測定のため先にWASMを前提にしない | 性能測定(検証計画)で負荷目標を満たせない場合 → 該当モジュールをWASM化 |
| DEC-103 | ローカルサーバー | **Node.js** の単一プロセス。静的配信、パッチファイルの保存、エージェント用API、MCPアダプタを提供。待受は **127.0.0.1 のみ** | DEC-001/002。外部アクセス範囲を最小にする(調査した既存例は認証・制限を欠くものが多い: F-019-009, F-019-022, F-019-029, F-019-044) | 他ホストからの接続 → 対象外(後続) |
| DEC-104 | エンジンの実行場所 | 音声エンジンは**ブラウザのタブ内**。エージェントはローカルサーバーへ接続し、サーバーがタブへ中継する | 音を出す主体をブラウザに一本化する(DEC-001)。自動再生制限により音声開始にはユーザー操作が要る(F-021-018〜020) | サーバー側のヘッドレスエンジン → 後続(無人運転が必要になった場合) |
| DEC-105 | パッチの正本 | **単一のパッチグラフ(状態モデル)**を制御側(メインスレッド)が持ち、UIとエージェントの操作は同じコマンドで直列に適用する。エンジンには差分を送る | DEC-002。検証→適用→失敗時ロールバックの先行例(F-018-068, F-018-069) | — |
| DEC-106 | 保存形式 | **JSON**(版番号付き)。ブラウザ内の自動保存と、ローカルサーバー経由のファイル保存 | 先行例の多くがJSON(F-018-012, F-018-028, F-018-067)。人とエージェントが読める | バイナリ内部状態(遅延バッファ等)は既定で保存しない(データ契約で定義) |
| DEC-107 | サンプルレート | エンジンの `fs` は **AudioContext の実サンプルレート**に従う。既定で48000 Hzを要求し、得られた値を使う | 出力デバイスと異なるレートは再サンプリングで遅延が増えうる(F-021-008)。#2 COM-05は単一fsを前提にし、時間パラメータは `fs` から係数を再計算する | 固定48 kHz → 再サンプリングの遅延を受け入れる場合 |
| DEC-108 | レンダ量子 | 既定の128フレームで処理し、結果は1サンプル処理と一致させる(COM-05) | 既定128フレーム(F-021-005)。`renderSizeHint` はドラフト仕様(F-021-001)のため依存しない | — |
| DEC-109 | ライセンス方針 | 本製品のコードは自作。調査対象のコード・アセット・外観・商標は再利用しない。配布ライセンスは**未決**(OPEN-005) | #1のライセンス記録(GPL/AGPLの先行例が多い)。コピーレフトの混入を避ける | 第三者ライブラリの採用時は個別に確認 |
| DEC-110 | 出力保護の位置 | リミッターは**クリップ前の信号**に作用させる。順序は「MOD-IO-001 の音量・ミュート(クリップ前の値)→ 非有限値の検出と除去 → マスター音量 → リミッター → 最終クリップ(±1.0)」。MOD-IO-001 の±1.0クリップは、この最終クリップとして扱う(#2 の MOD-IO-001 を改訂) | 現行のMOD-IO-001はDEV出力を先に±1.0でクリップし、NaN/∞も0に置換するため、後段のリミッターと非有限値検出が働かない(独立レビュー A-1)。DEC-004「常時リミッター」を実質的に満たすには、リミッターがクリップより前にある必要がある | #2を改訂せず、製品段でしきい値を1.0未満にする案 → 過大入力時にクリップ歪みが先に出るため不採用 |
| DEC-111 | 音量を自動で上げない | パッチの読込・新規作成・置き換えを伴う取り消し/やり直し・緊急停止の解除・音声の開始/再開では、マスター音量を **min(現在値, 既定値)** にしてフェードインする。エージェント上限は変えない | 人が既定値より下げていた音量が、エージェントの `patch.load` 等で上がる経路を塞ぐ(独立レビュー A-2。REQ-S-004) | — |
| DEC-112 | 非有限値の検出 | 各モジュールがCOM-12で置換した回数をエンジンが集計し、通知する。出力段でも検出する | 出力段だけでは、上流で0に置換された非有限値を検出できない(独立レビュー A-1。REQ-S-006) | — |

## 4. 対象外・将来拡張(初期版を止めない)
- デスクトップアプリ配布、他ホストからの遠隔接続、複数人の同時編集、サーバー側ヘッドレスエンジン。
- #2で保留のモジュール(波形整形、空間系、複雑オシレータ、量子化、リング変調、ヴォコーダ)。
- MIDI出力、MPE、MIDI 2.0、OSC入出力、オーディオ入力、録音・書き出し。
- 他形式(VCV Rack `.vcv` 等)とのパッチ互換。
