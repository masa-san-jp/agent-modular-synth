## 3. 知っておくこと(はまりやすい点)
- **パッチの正本はブラウザのタブにある。** サーバーは中継とファイル保存だけ。タブが開いていないと、ほとんどのコマンドは ERR-006 になる(例外: `module.list_types`、`patch.list`、`patch.read`、`performance.render`)。
- **人が `START` を押すまで音は出ない。** エージェントは音声を開始できない。
- **楽譜のパラメータの変化(`params`)は、パッチを変えない。** 音声側の値だけが動き、演奏が終わるとパッチの値に戻る。
- **パッチを置き換えると、音量は既定値へ下がる**(安全のため。再演奏 `performance.replay` でも下がる)。
- **状態を読む処理で、状態を変えない。** 以前、演奏の状態を読むだけで終わった楽譜を捨てていて、「演奏し終えた」の通知が抜けた(PR #45 で修正。`test/performance.test.ts` の VER-A-009g)。
- **エンジンの控え(ラッチ)**: つながっていない出力は毎サンプル写していない。読む前に `syncStale()` で写し直す(`src/engine/engine.ts`、`test/engine-latch.test.ts`)。
- **画面の値の名前**: 仕様の列挙型の値(日本語)は、`src/view/labels.ts` で画面用の語に替える。対応が抜けると単体試験が落ちる。
- **ブラウザ試験は、機械が混んでいると時間切れになることがある。** 単独で回し直して確かめる。
- **作業環境の制限**: 外部のサイトの多くは開けない(検索はできる)。X(旧 Twitter)は開けない。

## 4. 作業環境で実際に演奏するには
エージェント自身が演奏して確かめる手順(2026-11-24 に実施)。
1. サーバーを起動し、ヘッドレスのブラウザでタブを開き、人の役として `START` を押す(Playwright)。
2. MCP アダプタ(`dist/src/mcp/main.js`)を stdio で起動し、`batch` でパッチを組み、`score_play` で楽譜を送る。
3. `score_get_status` で残りの時間と prompt を読み、残りが尽きる前に次の楽譜を送る。
4. `performance_list` → `performance_render` で音声ファイルにする。

楽譜の実例は `demo/`(`piece.mjs`、`techno.mjs`)。音は聞けないので、ミキサー卓(`MOD-MIX-002`)の `meter_read` で音量と帯域を数値で確かめる(`docs/mcp-setup.md` の「演奏のしかた」)。
