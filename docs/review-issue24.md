## 4. 保留・受容・未達

| # | 内容 | 理由 | 次の扱い |
|---|---|---|---|
| W-12 | フェードがリミッターの前にある | 順序は製品仕様 §8.1 の決定(DEC-110)。安全側の問題ではなく、聞こえ方の問題。出力保護の定数と一緒に決めるのがよい | OPEN-010(出力保護の定数)と合わせてオーナーが判断 |
| W-17 の一部 | 中断と復帰を、実際のブラウザでは試験していない | ヘッドレスのブラウザで、OS による中断を起こす手段がない。同じ処理を、本物のワークレットの中身を使った単体試験で確かめている | 実機での確認を、手動の確認項目に入れる |
| S-5 | タブへのなりすまし | DEC-014(同じ利用者の権限のプログラムは信頼する)で受容済み。`docs/mcp-setup.md` に「エージェントにシェルを与えると、人のみの境界は効かない」と明記した | 方針を変えるならオーナーが判断(OPEN-007) |
| C-14 | 上限の定数が2か所 | 上限を変えるのは試験だけで、製品では既定値しか使わない。値は一致している | 上限を設定で変えられるようにするときに1つにする |
| 既知 | `module.list_types` の未達の項目 | 種別の定義表に、分類・単位・未接続時の値・列挙の選択肢を持たせる作業が要る(18 モジュール分) | 別の Issue にする |

## 5. 確かめた内容と、確かめられなかった点

確かめた内容(2026-11-20):

- `npm run check`(ビルド、型検査、単体試験、検証例の網羅、仕様文書の検査)
- ブラウザ試験4種(`npm run test:e2e`。ヘッドレスの Chromium)

確かめられなかった点:

- 実際の音(スピーカー・ヘッドホンでの聞こえ方)。試験は数値で確かめている。
- Chromium 以外のブラウザ。単一タブの鍵(Web Locks)は、ない場合にサーバーの検査だけに戻るようにしてあるが、他のブラウザでは動かしていない。
- OS による音声の中断と復帰(上の W-17)。
- 実際の MCP クライアント製品での動作(OPEN-008)。
- 枠への埋め込みを使った攻撃そのもの。ヘッダが付くことと、枠の中でアプリが動かないことは確かめた。
- Windows と macOS。試験は Linux で実行した。
