# MCP アダプタの設定手順

MCP(Model Context Protocol)に対応したクライアント(AI エージェントのアプリやコマンドラインのツール)から、このシンセを操作するための手順。
MCP アダプタは、共通コマンド([操作契約](../specifications/synthesizer/operation-contract.md) §6)を1対1でツールにする薄い変換層で、独自の状態・機能を持たない(操作契約 §17)。

```
MCP クライアント ──stdio──> MCP アダプタ ──HTTP(127.0.0.1 だけ)──> ローカルサーバー ──> ブラウザのタブ(パッチと音声)
(エージェント)            (dist/src/mcp/main.js)                     (npm run dev)
```

- パッチと音声を持つのはブラウザのタブ。アダプタとサーバーは中継するだけ。
- アダプタが通信する相手は、同じマシンのローカルサーバーの `POST /api/command` だけ。外部には何も送らない。

## 1. 準備(1回だけ)
```
npm install      # 依存を入れる(Node.js 22 以上)
npm run build    # dist/ を作る(MCP アダプタは dist/src/mcp/main.js)
```

## 2. サーバーを起動する
```
npm run dev
```
- 表示された URL(既定 `http://127.0.0.1:47800/`)とエージェント用トークンが出る。**このターミナルは開いたままにする**(閉じる・Ctrl+C でサーバーが止まる)。
- サーバーは起動のたびに新しいトークンを発行し、ファイル `~/.agent-modular-synth/agent-token` に書く(所有者だけが読める。終了時に消す)。MCP アダプタはこのファイルを読むので、**トークンを手で写す必要はない**。

## 3. ブラウザで開いて、音声を開始する
1. 表示された URL をブラウザで開く(タブは1つだけ。2つ目のタブはセッションにならない)。
2. 画面の「音声開始」を押す。**音声を開始できるのは人だけ**で、エージェントは開始できない。
   - 音声を開始する前でも、エージェントはパッチの編集・保存・読出しができる(音は出ない)。

## 4. MCP クライアントに登録する
クライアントの設定ファイル(場所と書式は各クライアントの説明を参照)に、stdio のサーバーとして登録する。多くのクライアントは次の形の JSON を受け付ける。`<リポジトリ>` は、このリポジトリを置いた場所の**絶対パス**に置き換える。

```json
{
  "mcpServers": {
    "modular-synth": {
      "command": "node",
      "args": ["<リポジトリ>/dist/src/mcp/main.js"]
    }
  }
}
```

サーバーの待受ポートを変えている場合や、トークンを環境変数で渡したい場合は `env` を足す。

```json
{
  "mcpServers": {
    "modular-synth": {
      "command": "node",
      "args": ["<リポジトリ>/dist/src/mcp/main.js"],
      "env": {
        "SYNTH_URL": "http://127.0.0.1:47800"
      }
    }
  }
}
```

コマンドを1行で登録する形のクライアントでは、`node <リポジトリ>/dist/src/mcp/main.js` を指定する。

### 環境変数
| 名前 | 既定 | 内容 |
|---|---|---|
| `SYNTH_URL` | `http://127.0.0.1:47800` | ローカルサーバーの場所。`http://127.0.0.1:<ポート>` または `http://localhost:<ポート>` だけ。**それ以外(他のホスト、https、経路つき)を指定すると、アダプタは起動しない** |
| `SYNTH_AGENT_TOKEN` | なし | エージェント用トークン。指定するとファイルより優先する。トークンはサーバーの起動のたびに変わるので、通常は指定せず、下のファイルに任せる |
| `SYNTH_TOKEN_FILE` | `~/.agent-modular-synth/agent-token` | トークンのファイルの場所。**サーバーとアダプタの両方**が見る。変える場合は、`npm run dev` を実行する側と MCP クライアントの `env` の両方に同じ値を指定する |
| `SYNTH_CLIENT_ID` | `mcp` | 応答や通知の `actor.client_id` に出る表示用の名前(1〜64文字)。権限には関係しない |

サーバー側の環境変数は `PORT`(待受ポート。変えたらアダプタの `SYNTH_URL` も合わせる)、`SYNTH_PATCH_DIR`(保存フォルダ)、`SYNTH_TOKEN_FILE`。

## 5. 使い方の目安
- まず `module_list_types`(モジュールの種別・ポート・パラメータの範囲)と `patch_get`(現在のパッチとリビジョン)を読む。
- 複数の変更は `batch` にまとめる(全部成功したときだけ適用され、取り消しも1回で済む)。
- 変更系のツールには `expected_revision`(自分が見たリビジョン)を付けると、人や他のエージェントの変更とぶつかったときに何も変えずに失敗する(`ERR-008`)。その場合は `patch_get` で読み直す。
- 応答が受け取れなかったときに同じ操作を送り直すなら、`idempotency_key`(1〜64文字)を**最初から**付けておく。アダプタは自動で再送しない。
- 鍵盤なしで音を確かめるには、発振器の出力を `out` の `IN_L` / `IN_R` へつなぐ、またはクロックとシーケンサで鳴らす。測定は `MOD-IO-003`(メーター)を置いて `meter_read` で読む。

例(発振器を1つ足して、出力の左へつなぐ):
```json
{
  "ops": [
    {"command": "module.add", "args": {"type": "MOD-OSC-001", "id": "vco1"}},
    {"command": "cable.connect", "args": {"from": {"module": "vco1", "port": "sine"}, "to": {"module": "out", "port": "IN_L"}}}
  ]
}
```
`batch` の `ops` の中の `command` は、ツール名ではなく `.` 区切りのコマンド名で書く。

### ツール(25個)
ツール名は、共通コマンド名の `.` を `_` に置き換えたもの。各ツールの入力は、そのコマンドの引数に、任意の `expected_revision` と `idempotency_key` を加えたもの。

| 分類 | ツール |
|---|---|
| 読出しのみ | `module_list_types`、`module_get`、`patch_get`、`patch_list`、`patch_read`、`meter_read`、`engine_get_status`、`score_get_status` |
| 演奏 | `score_play`(楽譜を送る)、`score_stop`(止める) |
| パッチを変える(`history_undo` で取り消せる) | `module_add`、`module_remove`、`module_move`、`cable_connect`、`cable_disconnect`、`param_set`、`batch`、`patch_new`、`patch_load`、`patch_set_meta` |
| 取り消し・やり直し | `history_undo`、`history_redo` |
| パッチ以外を変える(取り消し不可) | `patch_save`、`engine_panic`、`output_set_level` |

### 結果の読み方
- 結果は、共通コマンドの応答(操作契約 §3.2)そのままの JSON(テキスト1つ)。`ok`、`revision`、`audio_state`、`result`、`warnings` などが入る。
- 失敗(`ok: false`)は、ツールの**エラー結果**として返る。`error.id`(`ERR-…`)、`error.code`、`error.message`、`error.details` がそのまま入っている。失敗した要求は状態を変えない。
- `error.id` が `null` で `error.code` が `adapter_…` のものは、サーバーまで届かなかった等の、アダプタ自身が作った失敗(下の「困ったとき」)。

### 演奏のしかた(楽譜を書いて送る)
**このシンセは器で、楽譜を考える機能は持たない。** 楽譜を書くのは、つないだエージェント(Claude Code、Codex など)。シンセは、届いた楽譜をそのとおりに鳴らし、人が書いた指示を預かって渡すだけ。

エージェントは、音符を1つずつその場で鳴らすのではなく、**楽譜**(どの音を、何拍目から、何拍のばすかの並び)をまとめて送る。音は音声側の時計で正確に鳴るので、考える時間や通信の時間は演奏のずれにならない。

1. 音が出るパッチを用意する。MIDI-CV(`MOD-IO-002`)の `PITCH` をオシレータへ、`GATE` をエンベロープや VCA へつなぐ。和音を鳴らすなら `voices` を増やす。
2. `score_play` で楽譜を送る。`tempo_bpm` を付けると、位置と長さの単位が拍になる。`length` は小節の区切りに合わせる(次の楽譜がそこから始まる)。
   ```json
   { "tempo_bpm": 100, "length": 4,
     "notes": [ { "t": 0, "dur": 1, "note": 60 }, { "t": 1, "dur": 1, "note": 64 },
                { "t": 2, "dur": 2, "note": 67 } ] }
   ```
3. 応答の `remaining`(予約の末尾までの秒)が尽きる前に、次の楽譜を `score_play` で送る。前の楽譜の終わりに、切れ目なく続く。間に合わなくても演奏は再開するが、間が空く。長めの楽譜(数小節〜数十秒)を先に送っておくと、次を考える時間ができる。
4. 人は画面の「演奏への指示」に指示を書ける。次の楽譜を書く前に `score_get_status`(または `score_play` の応答)の `prompts` を読み、`acked: false` の指示を踏まえる。踏まえた楽譜には `ack_prompt`(その指示の `id`)を付ける。画面に「反映済み」と出る。
5. 音色を動かしたいときは、楽譜に `params`(パラメータの変化)を書く。「8 拍目から 8 拍かけてフィルタを開く」なら次のとおり。位置は拍に正確に合う。変わるのは音声側の値だけで、パッチは変わらない。演奏が終わるとパッチの値に戻る。
   ```json
   { "tempo_bpm": 132, "length": 16, "notes": [ … ],
     "params": [ { "t": 8, "dur": 8, "module_id": "vcf", "param": "cutoff", "value": 2 } ] }
   ```
6. 止めるときは `score_stop`。予約を全部やり直すときは `score_play` に `mode: "replace"` を付ける。

- 音が出るのは、人が「音声開始」を押した後だけ(それまでは `ERR-301`)。緊急停止や音声の停止で、予約済みの楽譜はすべて捨てられる。
- 演奏はパッチの編集ではない。リビジョンは進まず、`history_undo` の対象にもならない。
- 上限: 楽譜1つは 2000 音符・600 秒まで。予約は合計 10000 音符、900 秒先まで。

## 6. できること・できないこと
| できる | できない(人だけができる・または存在しない) |
|---|---|
| モジュールの追加・削除・移動、接続、パラメータの設定、一括適用 | **音声の開始・再開**(画面の「音声開始」) |
| パッチの読出し、新規作成、名前を付けて保存、読込、一覧 | **緊急停止の解除**(画面の操作) |
| 取り消し・やり直し(人の操作も含めた1本の履歴) | **保存パッチの削除** |
| **楽譜による演奏**(予約、続き、停止)と、人からの指示の読出し | 演奏への指示の送信(人が画面から書く) |
| メーターと状態の読出し | 人が保存したファイルの上書き(上書きできるのは、最後にエージェントが保存したファイルだけ) |
| **緊急停止**(全消音) | 人が決めた上限を超える音量の設定、上限の変更 |
| 上限以下へのマスター音量の設定 | 保存フォルダの外の読み書き、サーバーの停止、他のホストへの送信、コードの実行 |

- 人だけができる操作(`engine.start`、`engine.release_panic`、`patch.delete`)は、ツールとして存在しない。
- 通知(他の人・エージェントによる変更の知らせ)は転送されない。最新の状態は `patch_get` で読み、`expected_revision` で食い違いを検出する。
- 演奏は楽譜で行う(上の「演奏のしかた」)。その場で1音ずつ鳴らすツールはない。人への指示の送信(`prompt.send`)は人だけができる。
- 音量の上限は「人が最後に設定したマスター音量」。エージェントは音量を下げられるが、上限を超えては上げられない(超える要求は `ERR-302` で拒否され、上限の値に丸められることもない)。

## 7. 困ったとき
| 症状(結果の `error`) | 原因と対処 |
|---|---|
| `code: adapter_server_unreachable` | サーバーが起動していない、またはポートが違う。`npm run dev` を実行する。ポートを変えているなら `SYNTH_URL` を合わせる。サーバーを起動すれば、アダプタやクライアントを起動し直す必要はない。`details.applied` が `"unknown"` のときは、要求が適用されたか分からない(`patch_get` で確かめる) |
| `code: adapter_no_token` | トークンのファイルがない(サーバーが起動していない、または `SYNTH_TOKEN_FILE` がサーバーとアダプタで違う)。サーバーを起動する。ファイルを使えない環境では、サーバーが表示したトークンを `SYNTH_AGENT_TOKEN` に指定する |
| `id: ERR-004`(`unauthorized`) | トークンが違う。`SYNTH_AGENT_TOKEN` に古いトークンを指定していないか確かめる(サーバーの再起動で変わる。指定をやめればファイルから読む)。サーバーを2つ起動していると、後から起動した方のトークンがファイルに入る |
| `id: ERR-006`(`no_session`) | ブラウザのタブが開かれていない。表示された URL を開く。`module_list_types`・`patch_list`・`patch_read` だけはタブがなくても使える |
| `id: ERR-301`(`audio_not_running`) | 音声が開始されていない。人が画面の「音声開始」を押す |
| 成功するのに音が出ない | `engine_get_status` を読む。`audio_state` が `running` でない → 人が「音声開始」を押す。`panic` が `true` → 人が緊急停止を解除する。`output.level_db` が低い → 人が音量を上げる。どれでもなければ、`out` の `IN_L` / `IN_R` まで信号がつながっているかを `patch_get` で確かめる |
| `id: ERR-007`(`timeout`) | タブが時間内に応答しなかった。適用されたかは不明なので、`patch_get` で確かめる |
| `id: ERR-008`(`revision_conflict`) | 他の操作でリビジョンが進んだ。`patch_get` で読み直してから送り直す |
| `code: adapter_bad_response` | `SYNTH_URL` が、このシンセのサーバーでない別のプログラムを指している |
| `id: ERR-001`、`details.reason: too_deep` | 要求の入れ子が深すぎる(64 段まで。モジュールの `ui` は 8 段まで) |
| `id: ERR-010`、`details.reason: too_many_pending` / `not_forwarded` | サーバーがタブへ要求を送れなかった(応答待ちが多すぎる、タブへの送信が詰まっている)。この要求は適用されていない。少し待って送り直す |
| アダプタが起動しない(クライアントが接続に失敗する) | `SYNTH_URL` が `http://127.0.0.1:<ポート>` / `http://localhost:<ポート>` の形でない(アダプタは標準エラーに「起動できません」と理由を書く)。または `args` のパスが違う・`npm run build` をしていない |
| ツールが見えない・古い | `npm run build` をやり直し、MCP クライアント側でサーバーを再読込する |

手で確かめるには、アダプタを直接起動する: `node dist/src/mcp/main.js`(または `npm run mcp`)。標準エラーに接続先が表示され、標準入力から MCP のメッセージを待つ(Ctrl+C で終了)。

## 8. 安全についての注意
- サーバーは 127.0.0.1 だけで待ち受け、トークンのない要求を拒否する。アダプタは 127.0.0.1 / localhost 以外へは接続しない。
- トークンのファイルは所有者だけが読める(0600)。同じ利用者の権限で動くプログラムは信頼する方針(plans/decisions.md DEC-014)で、他の利用者からは読めない。Windows ではファイルの権限の指定が効かないので、利用者のフォルダの権限に依存する。
- **エージェントにシェルや任意の HTTP の実行を許すと、「人だけができる操作」の境界は効かない。** この境界(音声の開始、緊急停止の解除、保存パッチの削除、音量の上限)が守られるのは、エージェントが MCP のツール(または エージェント用API)だけを使う場合に限る。同じ利用者の権限でコマンドを実行できるエージェントは、保存フォルダのファイルを直接読み書きでき、画面(index.html)に埋め込まれたタブ用トークンを読んで、タブが開いていない間にタブになりすますこともできる(同じ利用者の権限のプログラムは信頼する方針: DEC-014)。人のみの境界を保ちたいときは、エージェントに与える道具を MCP のツールだけにする。
- アダプタは、所有者以外が読み書きできる権限のトークンのファイル、所有者の違うファイルを使わない(`adapter_no_token`、`details.reason: "insecure"`)。権限を 600 に直すか、サーバーを起動し直す。
- トークンを設定ファイルや記録に書き残さない(`SYNTH_AGENT_TOKEN` を使う場合)。サーバーを再起動すれば古いトークンは無効になる。
