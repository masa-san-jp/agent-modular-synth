# 実装メモ: 仕様に記述がなく、実装側で補った解釈

モジュール仕様(`specifications/modules/`、v0.2)と共通規約(v0.5)に書かれていなかった点を、実装でどう扱ったかの一覧。仕様への追記の候補であり、仕様の正本ではない。各項目の末尾に、Issue #24(2026-11-20)での反映先を記す(common.md は 0.6。モジュール仕様は版 0.2 のまま、日付つきの注記として追記)。検証例の期待値は、どれも仕様の表のまま使っている。

## 実装時に見つかった問題
| 項目 | 内容 | 対処 | 反映(Issue #24) |
|---|---|---|---|
| ゲートの OFF 閾値(COM-04) | ポート値は float32 なので、0.1 V の入力は 0.1000000015 になる。閾値を倍精度の 0.1 で持つと「0.1 V 以下で OFF」が偽になり、ちょうど 0.1 V でゲートが下がらなかった(MOD-LGC-001 TV-02、MOD-CLK-002 TV-07、MOD-RND-001 TV-04 が不合格になる) | `src/engine/util.ts` の `GATE_OFF` を float32 に丸めた値にした。**COM-04 に「閾値との比較は float32 のポート値で行う」と追記が必要** | 反映済み: common.md COM-04(2026-11-16 に追記。0.6 の変更履歴に記録) |
| MOD-LFO-001 TV-04 (b) | 期待値 `1.0417e-7`(有効5桁)の丸め誤差(約3.3e-12)が、許容誤差(1e-12)より大きかった。式どおりの実装が不合格になった | 仕様の期待値を `0.005/48000 = 1.0416666667e-7` に訂正(仕様 §9 に記録)。式と挙動は変えていない | 反映済み: MOD-LFO-001 §10 末尾(2026-11-16 の訂正) |
| MOD-RND-001 の表記の揺れ | seed=12345 の NOISE 先頭値が、TV-08 (b) と TV-10 (e)/TV-11 (f) で約3e-10 違う | 許容誤差(1e-6)の内側で、どちらも合格。仕様の表記を揃えるのが望ましい | 未反映(理由: 検証例の期待値は変えない。どちらも許容誤差内) |

## 共通(エンジン核)
| 項目 | 扱い | 反映(Issue #24) |
|---|---|---|
| ケーブル遅延値の初期値 | 最初のステップでは、1チャンネルの 0 V | common.md COM-06 |
| 生成時のパラメータで決まる初期状態 | モジュールの生成関数は `fs` だけを受ける。パッチの読込側が「パラメータを設定した後に `reset()` を呼ぶ」ことで、初期値がパラメータに依存する状態(MOD-IO-001 の音量の平滑値、MOD-CLK-002 のカウンタ初期値 `division − 1`、MOD-IO-002 の `voices`)を初期化する。`src/audio/core.ts` の読込はそうしている | common.md COM-10 |
| 真偽型のパラメータ | 仕様の「有限の0以外は1」(MOD-IO-001 `mute`、MOD-SEQ-001 `gate[i]`・`run`)は、共通の正規化(範囲へクランプ)では表せないので、各モジュールが設定値から直接判定している | common.md COM-13(現在の実装は、共通の正規化 `normalizeParam` が真偽型を「有限の0以外は1」として扱う) |
| スナップショット内の数値 | JSON で表せない NaN・±∞・−0 は文字列で保存する(−0 が +0 になるとビット同一が崩れる) | data-contract DAT-15(−0 の表記を追加。NaN・±∞ は記載済み) |
| `N` が変わるとき | 増えたエンジンは初期状態、減った分は使わない(再び増えたら初期状態から) | common.md COM-08 |
