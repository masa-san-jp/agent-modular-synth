# 発振器(MOD-OSC-001)の折り返し成分: 帯域制限の前と後

- 測定日: 2026-11-27
- 対象: Issue #58。MOD-OSC-001 の鋸歯・矩形・三角を、ナイーブな波形(仕様版 0.2)から帯域制限した波形(仕様版 0.3。2サンプルの PolyBLEP / PolyBLAMP。DEC-028)に置き換えた。
- 測定方法: MOD-OSC-001 §6「音質要件」(VER-NF-007a)。道具は `tools/measure-osc-aliasing.mjs`(`npm run measure:osc-aliasing`)。
- **合否は出していない。** 音質の数値目標は未決(OPEN-006)。この文書は、目標を決めるための材料である。

## 1. 結論
1. **440 Hz・10 kHz と、4 kHz の近く(4186 Hz)で、3 波形とも折り返し成分が下がった。** 下がった量は 8〜12 dB(fs = 48000、全帯域)。
2. **4000 Hz ちょうどは、この測定方法では前も後も折り返し成分が見えない。** 4000 Hz は fs = 48000 の 1/12 で、波形の周期がちょうど 12 サンプルになる。折り返した成分がすべて高調波の位置に重なるので、高調波を除いて山を探すこの方法では拾えない(前後とも −150 dB 前後で、計算の丸めの大きさ)。そのため 4000 Hz の代わりに、周期が整数サンプルにならない 4186.0096 Hz(`pitch` = +4 V)を測った。同じ 4000 Hz を fs = 44100 で測ると、3 波形とも 9〜14 dB 下がった(§3.2)。
3. 正弦は変えていない。前後で同じ値である。
4. 帯域制限の代わりに、高い倍音が少し下がる。440 Hz の鋸歯で、15 kHz の倍音が約 3 dB 下がる(§4)。
5. 1 つの発振器の 1 サンプルの計算時間は、約 116 ns → 約 153 ns(約 30 % 増。§5)。
6. デモ 6 曲を同じ楽譜で書き出し直すと、音量は変わらず、矩形波をそのまま鳴らす chiptune の差がいちばん大きかった(§6)。

## 2. 測定環境と方法
| 項目 | 値 |
|---|---|
| 機材 | 作業用のクラウドのコンテナ(共用)。Intel Xeon 2.10 GHz、4 コア |
| OS | Linux x64 |
| Node.js | v22.23.5 |
| 前(仕様版 0.2) | `main` の 4fef65a をビルドしたもの |
| 後(仕様版 0.3) | Issue #58 の変更をビルドしたもの |
| 生データ | `docs/perf/20261127-osc-aliasing/`(`before-v0.2-fs48000.json`、`after-v0.3-fs48000.json`、`before-v0.2-fs44100.json`、`after-v0.3-fs44100.json`) |

方法(MOD-OSC-001 §6):
- 既定のパラメータの VCO を、`pitch` 一定で 2^16 サンプル動かし、4 波形を取る。
- Hann 窓をかけて FFT し、振幅スペクトルを求める。
- 基本波とその整数倍の高調波(0 倍 = 直流を含む)の位置から ±3 ビンを除く。
- 残りのビンの山(両隣より大きいビン)のうち最大のものを折り返し成分とし、基本波の山との比 [dB] を出す。値が小さい(負に大きい)ほど、折り返し成分が少ない。
- 参考に、山を 20 kHz 以下に限った値も出した(可聴域。仕様の方法は全帯域)。

周波数の 4000 Hz は、`pitch` = log2(4000 / 261.6256) で与えた。4186.0096 Hz は `pitch` = +4 V(C8)である。

### 3.3 読み方
- 高い音ほど折り返し成分が多い。10 kHz の鋸歯は、後でも基本波の −21 dB の折り返し成分がある。帯域制限は折り返しを減らすが、なくしはしない。
- 矩形と三角の 4186 Hz・10 kHz は 12 dB 下がり、鋸歯の 4186 Hz は 8.5 dB だった。鋸歯の 4186 Hz で最大の山は 22.9 kHz(可聴域の外)にあり、20 kHz 以下に限ると 12.2 dB 下がっている。
- どこまで減らせばよいかは決めていない(OPEN-006)。

## 4. 方式の選び方(2サンプルと4サンプルの比較)
帯域制限の方式は、2サンプルの PolyBLEP / PolyBLAMP にした(DEC-028)。比べた4サンプルの多項式(3次 B スプラインの BLEP)の値を並べる。仕様の方法で、鋸歯を fs = 48000 で測った(4サンプルは比較のための試作で、製品には入れていない)。

```
| 周波数    | 方式       | 折り返し 全帯域 | 20 kHz 以下 | 倍音の下がり方(10 kHz / 15 kHz) |
|-----------|------------|-----------------|-------------|-----------------------------------|
| 440 Hz    | ナイーブ   | -34.4           | -36.0       | -0.7 / -0.5 dB                    |
| 440 Hz    | 2サンプル  | -42.5           | -47.3       | -1.8 / -3.4 dB                    |
| 440 Hz    | 4サンプル  | -50.4           | -58.6       | -3.0 / -6.2 dB                    |
| 4186.0 Hz | ナイーブ   | -15.3           | -16.4       | -0.4 / +0.4 dB                    |
| 4186.0 Hz | 2サンプル  | -23.8           | -28.6       | -1.1 / -1.3 dB                    |
| 4186.0 Hz | 4サンプル  | -32.2           | -40.8       | -1.7 / -3.1 dB                    |
| 10000 Hz  | ナイーブ   | -8.7            | -8.7        | 0 / 0                             |
| 10000 Hz  | 2サンプル  | -20.8           | -20.8       | 0 / 0                             |
| 10000 Hz  | 4サンプル  | -32.6           | -32.6       | 0 / 0                             |
```

倍音の下がり方は、理想の(帯域の制限のない)鋸歯の倍音の大きさ(基本波の 1/k)に対する比で、10 kHz・15 kHz 以下で最も高い倍音で見た。ナイーブの値が 0 でないのは、窓とビンの位置による誤差である。基本波が 10 kHz のときは、どちらも基本波そのものを見ているので 0 になる。

- 4サンプルは、折り返しがさらに約 8 dB 下がるが、15 kHz の倍音が約 6 dB 下がる(2サンプルは約 3 dB)。音がこもる側へ寄る。
- 4サンプルは、段差の前後 2 サンプルずつを補正するので、2サンプルより計算が多く、周波数が変わる途中の近似の誤差も大きくなる。
- minBLEP、オーバーサンプリング、帯域ごとの波形表は、状態・計算量・遅れ・規則が増える(DEC-028 の「退けた選択肢」)。

どの方式にするかは、音質の目標(OPEN-006)が決まった時点で見直す。

## 5. 計算時間
1 つの VCO(既定のパラメータ、440 Hz)の `step()` を 480 万回(100 秒分)呼び、1 回あたりの時間を測った。前と後を交互に 5 回ずつ動かし、各回の中央値を並べた。共用の機材なので揺れが大きい。

```
| 版        | 1 サンプルあたり(5 回の中央値の範囲) | 5 回の中央値 |
|-----------|----------------------------------------|--------------|
| 前(0.2)  | 108〜148 ns                            | 116 ns       |
| 後(0.3)  | 136〜172 ns                            | 153 ns       |
```

約 30 % 増えた。パッチ全体の負荷への影響は測っていない(VCO はパッチの一部で、ほかのモジュールの計算もある)。

## 6. デモ曲の書き出し(同じ楽譜で前と後)
`demo/` の 6 曲を、`node demo/render-wav.mjs demo/<曲>.mjs <出力>.wav` で前(0.2)と後(0.3)の両方で書き出した(fs = 48000、音量 −6 dB)。楽譜とパッチは同じで、違うのは VCO の波形だけである。

```
| 曲        | 長さ    | RMS 前 → 後     | 差の RMS(前の RMS に対する比) | 16 kHz 以上のパワーの割合 前 → 後 |
|-----------|---------|-----------------|---------------------------------|-----------------------------------|
| ambient   | 100.4 s | -20.0 → -20.0 dB| -40.8 dB                        | -88.7 → -88.7 dB                  |
| chiptune  | 87.6 s  | -23.3 → -23.3 dB| -12.6 dB                        | -22.4 → -22.6 dB                  |
| minimal   | 100.4 s | -25.7 → -25.8 dB| -29.1 dB                        | -52.1 → -52.1 dB                  |
| techno    | 95.5 s  | -20.1 → -20.2 dB| -39.9 dB                        | -46.7 → -46.7 dB                  |
| vaporwave | 106.8 s | -22.3 → -22.3 dB| -35.6 dB                        | -57.9 → -57.9 dB                  |
| piece     | 45.7 s  | -20.1 → -20.1 dB| -41.0 dB                        | -89.3 → -89.3 dB                  |
```

- 6 曲ともファイルの中身は変わった(MD5 が違う)。音量(RMS)は 0.1 dB 以内で同じ。
- 違いが大きいのは chiptune(差が前の −12.6 dB)。矩形波をフィルタを通さずに鳴らす曲で、高い音の段差の補正が効く。ほかの 5 曲は VCO の後にローパスフィルタがあり、差は −29〜−41 dB と小さい。
- この表は数値の比較で、聞き比べの評価ではない。書き出した音声(FLAC)はリポジトリに入れず、作業用の共有フォルダ(`synth-demos/20261127-osc-band-limited/`)に置いた。

## 7. 再現の手順
```

node tools/measure-osc-aliasing.mjs --fs 44100 --json after-44100.json
```
