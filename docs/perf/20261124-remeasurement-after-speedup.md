# 高速化の後の再測定(ブラウザでの負荷、サーバーの中での書き出し)

- 測定日: 2026-11-24
- 対象: Issue #48(引き継ぎ文書の A・B)。PR #47 のエンジンの高速化の後に、ブラウザの中とサーバーの中で測り直した。
- **合否は出していない。** 遅延・負荷の目標は未決(OPEN-001)。この文書は、目標を決めるための材料である。

## 1. 結論
1. **ブラウザの中でも、エンジンの高速化がそのまま効いている。** 連鎖 16 本(54 モジュール)の負荷の平均は 0.562 → 0.351。
2. **108 モジュール(連鎖 32 本)が、ブラウザで実時間に収まるようになった。** 高速化の前は音声の時計が遅れ(0.984)、音が途切れていた。今回は 1.000。214 モジュールは、まだ間に合わない(0.714)。
3. **タブで音声を動かしたままでも、サーバーの中での書き出しはほとんど遅くならない。** 41 モジュール・93.4 秒の音声の書き出しにかかった時間は次のとおり。
   - タブなし: 37.7 秒
   - タブで同じパッチを鳴らしたまま: 38.5 秒(2 % 増)
   - 書き出しの間も、タブの音声は途切れなかった(時計の比 1.000)
   - 高速化の前に測った 128 秒(タブで音声を動かしたまま)のような遅れは、出なかった
4. 書き出したファイルは、3 通りで同じだった(MD5 が一致)。3 通りとは、タブなし・タブあり、およびサーバーを使わないコマンド(`npm run render`)である。

## 2. 測定環境
`docs/perf/20261123-performance-measurement.md` と同じ種類の機材である。共用の機材なので、数 % の揺れがある。

| 項目 | 値 |
|---|---|
| 機材 | 作業用のクラウドのコンテナ(共用)。Intel Xeon 2.10 GHz、4 コア、メモリ 16 GiB |
| OS | Linux x64 |
| ブラウザ | Chromium 158(ヘッドレス。音声の出力機材なし) |
| Node.js | v22.23.5 |
| サンプルレート / ブロック長 | 48000 Hz / 128 サンプル |
| 生データ | `docs/perf/20261124-container/browser.json`、`render.json` |

前回(2026-11-23)のブラウザは Chromium 153 だった。ブラウザの版の違いも、差に含まれている。

## 3. 結果

### 3.1 負荷(ブラウザ。`npm run bench:browser`)
**負荷値** = 1 ブロックの処理時間 ÷ 1 ブロックの再生時間。1.0 を超えたブロックは、実時間に間に合っていない。

| パッチ | モジュール | 負荷 平均(前回 → 今回) | 1.0 を超えたブロック(今回) | 音声の時計の進み ÷ 実時間(前回 → 今回) |
|---|---|---|---|---|
| BP-0(空) | 1 | 0.009 → 0.008 | 0 / 3733 | 1.000 → 1.000 |
| BP-1(基本の 1 声) | 6 | 0.055 → 0.049 | 1 / 3734 | 1.001 → 1.000 |
| BP-POLY(16 声) | 6 | 0.245 → 0.192 | 6 / 3743 | 1.000 → 1.000 |
| BP-ALL(全種を各 1 個) | 18 → 20 | 0.154 → 0.149 | 1 / 3741 | 0.999 → 1.001 |
| BP-N N=1 | 4 | 0.036 → 0.037 | 0 / 3746 | 1.000 → 0.999 |
| BP-N N=2 | 8 | 0.078 → 0.064 | 0 / 3733 | 1.000 → 0.999 |
| BP-N N=4 | 14 | 0.154 → 0.108 | 2 / 3746 | 1.000 → 0.999 |
| BP-N N=8 | 28 | 0.301 → 0.189 | 0 / 3739 | 1.000 → 1.000 |
| BP-N N=16 | 54 | 0.562 → **0.351** | 18 / 3733 | 1.000 → 1.000 |
| BP-N N=32 | 108 | 0.973 → **0.687** | 124 / 3751 | **0.984 → 1.000** |
| BP-N N=64 | 214 | 1.841 → 1.377 | 2660 / 2660 | 0.530 → 0.714 |

- **BP-ALL の数え方**: 前回の後にモジュールが 2 種増えた(MOD-SAT-001、MOD-MIX-002)。そのため BP-ALL は 18 → 20 モジュールで、そのままは比べられない。
- **N=32 で 1.0 を超えたブロック**: 124 個(3 %)あった。それでも時計の比は 1.000 で、続けて遅れることはなかった。ブラウザは約 10 ms 分をまとめて処理するので、単発の超過は吸収される。ただし、余裕は小さい。
- **パーセンタイル**: 前回と同じく、この環境の音声スレッドの時計は 1 ms 刻みである。99 % の値は 0.4 刻みの目安にとどまる。

### 3.2 遅延(ブラウザ。同じ測定)
| 区間 | 前回 | 今回 |
|---|---|---|
| エージェントの往復(HTTP)中央値 / 95 % | 2.7 / 4.6 ms | 3.1 / 6.1 ms |
| エージェントの往復(MCP)中央値 / 95 % | 3.1 / 6.2 ms | 7.2 / 12.6 ms |
| 音声側の適用 平均 / 最大 | 5.7 / 10 ms | 4.6 / 10 ms |

- MCP の往復が前回より長くなった。原因は調べていない。共用の機材の揺れの範囲か、それ以外かは、この 1 回では区別できない。エンジンの変更は、この区間(MCP アダプタ → サーバー → タブの応答)の計算には関わらない。

### 3.3 サーバーの中での書き出し(`npm run bench:render`)
曲は `demo/techno.mjs`(41 モジュール、楽譜 6 個、演奏の長さ 91.4 秒 + 余韻 2 秒 = 93.4 秒)。

| 条件 | 所要 | 実時間の何倍の速さ |
|---|---|---|
| サーバーを使わないコマンド(`npm run render`) | 38.5 秒(`time` の値) | 2.43 |
| サーバー、タブなし | 37.7 秒 / 38.4 秒 | 2.48 / 2.43 |
| サーバー、タブで同じパッチの音声を動かしたまま | 38.5 秒 / 39.1 秒 | 2.42 / 2.39 |

- **繰り返し**: サーバーでの 2 条件は、2 回測った(`/` の左が 1 回目、右が 2 回目)。2 回とも、タブありはタブなしより 2 % 長かった。
- **曲の版**: 前回の値(62.6 秒 → 37.4 秒、80.2 秒の音声)とは、曲の版が違う。今の `demo/techno.mjs` は楽譜が 6 個で長さも違うので、所要時間の比較は「実時間の何倍の速さ」で見る(前回の高速化の後は 2.14 倍、今回は 2.4 倍前後)。
- **128 秒との違い**: 高速化の前は、タブで音声を動かしたまま 128 秒かかった。今回、タブありとタブなしの差は 2 % だった。理由は、次の 2 つと見ているが、確かめてはいない。
  - タブの音声の計算が軽くなり、4 コアのうち 1 つで余裕をもって収まるようになった。
  - 書き出しは別のコアで動く(別スレッド)。
- **書き出しの間のタブの音声**: 時計の比は 1.000 で、途切れなかった。
- **書き出したファイル**: 3 条件ともバイト同一(MD5 `c463729cc42c273cbaf81eab0ce77ae2`)。

## 4. 測り方(手元の機材で繰り返すとき)
```
npm install
npm run bench:browser   # ブラウザでの負荷と遅延。約 3 分。結果: bench/results/browser.json
npm run bench:render    # サーバーの中での書き出し。約 2 分。結果: bench/results/render.json
```
- `bench:render` は、まず `demo/make-performance.mjs` で曲の演奏データを作り、次の 2 つを続けて測る。
  - タブなしでの書き出し
  - タブで同じパッチの音声を動かしたままでの書き出し
- 結果の JSON を渡してもらえれば、この表にまとめる。

## 5. 確かめられなかった点
- オーナーの手元の機材での値(OPEN-001。Issue #50)。
- 実際の出力機材での音切れ。ヘッドレスのブラウザには出力機材がない。
- 繰り返し。ブラウザでの負荷は 1 回だけで、値のばらつきは測っていない。書き出しは 2 回だけである。
- 書き出しを 2 件以上同時に頼んだときの所要時間。
- 高速化の前の 128 秒を、同じ曲・同じ手順で測り直すこと。前回の手順と演奏データが残っていない。
