# 手元の LLM に演奏させる(ターミナル)

Ollama などで動かしている手元の LLM(例 `gpt-oss:20b`)に、ターミナルからシンセを演奏させる手順。Issue #55、DEC-027。

```
LLM(Ollama / OpenAI 互換) <──HTTP──> agents/local-llm(このプログラム) ──HTTP(127.0.0.1)──> ローカルサーバー ──> ブラウザのタブ(パッチと音声)
```

- このプログラムは**製品の外**にある、「外からつないだエージェント」の実例である。製品(サーバーとタブ)の中に推論は入れない(DEC-018)。
- **ツール**: MCP アダプタと同じ 30 個を、LLM の関数呼出しとして渡す(`src/mcp/tools.ts`)。パッチ作りも演奏も、LLM に任せる。
- **権限**: エージェントの権限はサーバーが守る。音声の開始、緊急停止の解除、パッチの削除、上限を超える音量はできない。
- **送り先**: 送り先は、同じマシンのローカルサーバーと、指定した LLM の接続先だけ。

## 1. 準備(1 回だけ)
1. Node.js 22 以上を用意し、このリポジトリで `npm install` を実行する。
2. Ollama を入れ、モデルを取ってくる。
   ```
   ollama pull gpt-oss:20b
   ```
   - 関数呼出し(tools)に対応したモデルが要る。
3. 文脈長は、プログラムが Ollama に `num_ctx` として渡す(既定 16384)。
   - 毎回の要求の先頭には、ツールの説明と指示文が入る。大きさは §3.1 の表のとおり。
   - 会話の履歴は、残りの長さに収まるように、プログラムが古い方から切る。
   - 文脈長が足りないときは、起動時に `[注意]` が出る。

## 2. 演奏させる
1. シンセを起動する(このターミナルは開いたまま)。
   ```
   npm run dev
   ```
2. 表示された URL(既定 `http://127.0.0.1:47800/`)をブラウザで開き、`START` を押す。**音声を始められるのは人だけ**である。
   - `START` を押す前にプログラムを起動しても、LLM はパッチを組んで待つ。
3. 別のターミナルでプログラムを起動する。
   ```
   npm run agent:local -- "暗いテクノを 3 分。だんだん激しく"
   ```
4. ターミナルに、LLM の発言と、呼んだツールが出る。
5. 画面の指示の欄に書くと、LLM に届く。LLM は、指示を踏まえた楽譜を送る。
6. 終了は `Ctrl+C`。予約済みの楽譜は最後まで鳴る。すぐ止めるには、画面の `PANIC` か「演奏を止める」を使う。

### オプション
| 引数 | 環境変数 | 既定 | 中身 |
|---|---|---|---|
| `--api ollama\|openai` | `LLM_API` | `ollama` | LLM の API の種類 |
| `--llm-url <URL>` | `LLM_URL` | ollama: `http://127.0.0.1:11434`、openai: `http://127.0.0.1:1234/v1` | LLM の接続先 |
| `--model <名前>` | `LLM_MODEL` | `gpt-oss:20b` | モデル |
| `--num-ctx <数>` | `LLM_NUM_CTX` | `16384` | 文脈長。Ollama には `num_ctx` として渡す。OpenAI 互換では、サーバーに設定した値に合わせる(履歴の長さの見積もりに使う) |
| `--tools compact\|full` | `LLM_TOOLS` | `compact` | ツールの説明の詳しさ(§3.1) |
| `--temperature <数>` | `LLM_TEMPERATURE` | モデルの既定 | 温度 |
| — | `LLM_API_KEY` | なし | OpenAI 互換の API の鍵(要るときだけ) |
| — | `SYNTH_URL`、`SYNTH_AGENT_TOKEN`、`SYNTH_TOKEN_FILE` | MCP アダプタと同じ | シンセの接続先とトークン。既定では、サーバーが書くトークンのファイルを読む |
| — | `SYNTH_CLIENT_ID` | `local-llm` | 変更の履歴と演奏データに残る名前 |

### OpenAI 互換の API(LM Studio、llama.cpp の `llama-server` など)
```
npm run agent:local -- --api openai --llm-url http://127.0.0.1:1234/v1 --model <モデル名> "静かなアンビエント"
```
- `/v1/chat/completions` の関数呼出し(`tools`)に対応したサーバーとモデルが要る。
- 文脈長は、サーバーの側で設定する。

## 3. 動き方
1. **最初の呼出し**: LLM に、演奏の目標と今の状態を渡す。LLM は、ツールを呼ばなくなるまで続けて呼べる。
   - 1 回に呼べるのは 24 回まで。これを超えると、いったん止めて考え直させる。
2. **起こす**: LLM がツールを呼ばなくなったら、プログラムは 1 秒ごとに `score_get_status` を見る。次のときに、状態を添えて LLM を起こす。

| 起こす理由(ログの表記) | とき |
|---|---|
| `audio_started` | 人が音声を開始した |
| `remaining_low` | 予約の残りが 8 秒以下になった(続きの楽譜を書く時間) |
| `new_prompt` | 画面から新しい指示が来た |
| `stopped` | 演奏が止まった(人が止めた、鳴り終わった)。続けるか終えるかを LLM が決める |

3. **終わり**: LLM が `[END]` と書いたら、予約が鳴り終わったところで終了する。
   - 終わった後でも、人の指示が来たら起こす。
4. **会話の長さ**: 小さいモデル向けに短く保つ。文脈長から逆算して、次の長さで切る。
   - 会話の履歴: 文脈長から、ツールの説明・指示文・返事の分(2048 トークン)を引いた残り。文字とトークンの比を少なめに 2 と見る。文脈長 16384 なら約 1.7 万文字。
   - ツールの結果: 1 件 6000 文字まで、かつ履歴の 3 分の 1 まで。

### 3.1 ツールの説明の大きさ
毎回の要求に入る固定の部分。トークン数は、gpt-oss のトークナイザー(o200k)で数えた(`js-tiktoken` の `o200k_base`)。

| 中身 | トークン |
|---|---|
| ツールの説明 `full`(MCP アダプタと同じ) | 11,216 |
| ツールの説明 `compact`(既定) | **4,145**(63 % 減) |
| 指示文(システムプロンプト) | 739 |

`compact` で除いたもの。ツールの数(30)、引数の形、引数ごとの説明は変えていない。
- 説明文の定型句: 「共通コマンド…、CMD-xx」「リビジョンが 1 進む」「結果は応答の封筒…」など
- 封筒の項目: `expected_revision`、`idempotency_key`。このプログラムは使わない
- 検査だけに使う項目: 数の上限、文字数、書式、余分な項目の禁止。検査はサーバーが行う

値の範囲(`minimum`、`maximum`)と選択肢(`enum`)は、モデルが値を選ぶのに使うので残した。

参考: 会話の中身の大きさ(テクノ曲の 41 モジュールのパッチで測った)

| 中身 | 文字 | トークン |
|---|---|---|
| `patch_get` の結果 | 10,912 | 4,116 |
| `module_list_types` の結果(1 種) | 1,355 | 416 |
| `module_list_types` の結果(全種) | 26,926 | 8,558 |
| 楽譜 1 つ(14.5 秒、`score_play` の引数) | 4,174 | 2,020 |
5. **ログの表記**

| 表記 | 中身 |
|---|---|
| `[モデル]` | LLM の発言 |
| `[ツール] 名前 引数 → ok / 失敗 …` | 呼んだツールと結果 |
| `[起こす] 理由` | LLM を起こした |
| `[終了]` | 演奏が終わって、プログラムが終了した |

## 4. 確かめたこと・確かめていないこと
- **確かめたこと**(作業用のクラウドの環境で)
  - 偽の LLM で、次の流れが動くことを、別のプロセスとして実際に起動して確かめた(`npm run test:local-llm-browser`)。
    1. パッチを組む
    2. 音声の開始を待つ
    3. 楽譜を送って鳴らす
    4. 続きを送る
    5. 終わりを宣言して終了する
  - 人のみのコマンドは呼べない。
  - 演奏データに `local-llm` の名前で残る。
  - Ollama と OpenAI 互換の API の要求と応答の形は、単体試験で確かめた(`test/local-llm.test.ts`)。
  - ツールの説明を縮めても、ツールの数と引数の形は変わらない。これも単体試験で確かめた。
- **確かめていないこと**: 本物のモデル(gpt-oss:20b を含む)で動かすこと。
  - 作業用の環境からは、Ollama とモデルの配布元につながらない。
  - そのため、次のことはまだ分からない。
    - モデルがツールを正しく呼べるか
    - どんな曲になるか
    - 1 回の考えにかかる時間

  オーナーの手元で確かめる(Issue #50)。
