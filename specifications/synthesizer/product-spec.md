# 製品仕様(本製品の採用判断・構成の正本)

版: 0.2 / 2026-11-13(独立レビューを受けて §2・§3.1・§5・§8.1 を更新)。要求は [requirements.md](requirements.md)(`REQ-…`)、判断と未決は [plans/decisions.md](../../plans/decisions.md)(`DEC-…`/`OPEN-…`)、モジュール挙動は [specifications/modules/](../modules/README.md)。本書はモジュール仕様の本文を複製しない。

## 1. 製品の概要
モジュールをケーブルで接続して音を作るモジュラーシンセ。ブラウザで動き、手元のPCで配信する(DEC-001)。人はUIで、エージェントは共通コマンドAPI(MCPアダプタ経由を含む)で、**同じパッチを同じコマンドで**操作する(DEC-002)。シンセ本体は未実装で、本書は設計である。

## 2. 利用シナリオ
成功時・失敗時の状態と受入結果を示す。コマンド名は [operation-contract.md](operation-contract.md)。
| ID | シナリオ | 主な操作 | 成功時の状態 | 失敗時の状態 | 受入(検証ID) |
|---|---|---|---|---|---|
| SC-H1 | 人がパッチを作る | モジュール追加 → 接続 → パラメータ調整 | パッチのリビジョンが進み、音に反映 | 無効な操作は拒否され、状態は不変。理由をUIに表示 | VER-F-001〜003 |
| SC-H2 | 人が演奏する | 音声開始(クリック)→ MIDIまたは画面鍵盤でノート(画面鍵盤はWeb MIDIと同じ経路でエンジンへ渡す演奏入力で、コマンド・履歴・リビジョンの対象外。エージェントからのノート送信は初期版に含めない) | MOD-IO-002 がpitch/gateを出力し発音 | MIDI非対応ブラウザでは画面鍵盤のみ(通知)。ブラウザが音声開始を許可しない場合は開始失敗をUIに表示し、状態は `stopped` のまま | VER-F-006 |
| SC-H3 | 人が保存・再開する | 保存 → 再読込 → 復元 | 構成・パラメータが一致。音声は停止状態から再開(ユーザー操作が必要) | 壊れた/未知の版のファイルは読込を拒否し、現在のパッチは不変 | VER-F-007, VER-F-008, VER-NF-006 |
| SC-A1 | エージェントが構築する | `module.list_types` → `batch`(追加・接続・設定) | 1リビジョンとして適用。人のUIにも反映 | 1つでも無効なら全体が適用されない(ロールバック) | VER-A-001, VER-A-002, VER-F-012 |
| SC-A2 | エージェントが変更・状態確認する | `patch.get` → `param.set` → `meter.read` | 変更が反映され、読出し値で確認できる | 存在しないID・範囲外の値は拒否(操作契約)。状態は不変 | VER-A-003, VER-A-004, VER-F-010 |
| SC-A3 | エージェントが保存・復元する | `patch.save` → `patch.load` | 名前付きパッチとして保存・復元 | 任意パスへの書込は不可(REQ-S-007) | VER-F-007, VER-S-007 |
| SC-X1 | 人とエージェントが引き継ぐ | 人が編集 → エージェントが`patch.get`で把握して続きを編集 → 人が取り消し | 両者の操作が1本の履歴に並ぶ。取り消しは直前の操作(誰のものでも)を戻す | 古いリビジョン前提の変更は競合として拒否(`expected_revision`指定時) | VER-A-005, VER-A-006, VER-F-009 |
| SC-X2 | 暴走時に止める | 緊急停止(UIボタン/`engine.panic`) | 出力が即時に無音。パッチは保持 | 音声が未開始なら何も鳴っていないので状態は不変(成功応答)。タブがない場合は「セッションなし」のエラー | VER-S-002 |

**実装範囲外の操作**: エージェントによる音声の自動開始(自動再生制限のため不可: F-021-018〜020、REQ-A-008)、任意ファイル・任意ホストへのアクセス(REQ-S-007)、遠隔からの接続(REQ-X-002)。

### 3.2 起動
1. 利用者がローカルサーバーを起動する(コマンド1つ)。サーバーは127.0.0.1で待受し、接続用トークンを発行して表示する(REQ-S-005)。**待受ポートは既定値に固定する**(ブラウザ内の自動保存はオリジン(ポート込み)単位のため、ポートが変わると自動保存から復元できない。既定ポートの番号は実装計画で決める)。
2. 利用者がブラウザで開く。UIが表示され、直前のパッチが自動保存から復元される(REQ-F-008)。**この時点で音は出ない**。

### 3.3 音声開始条件
- ブラウザは自動再生を許さず、AudioContextの開始にはユーザー操作が要る(F-021-018〜020)。本製品は、**利用者が「音声開始」を押したときにだけ** AudioContext を開始(`resume`)する。
- 音声状態: `stopped`(未開始)/ `running` / `suspended`(ブラウザやOSによる中断。F-021-012は確度low)。状態は全応答の封筒の `audio_state`、`engine.get_status`、通知で取得できる。
- ブラウザやOSが中断から自動で復帰させた場合(`suspended` → `running`)は受け入れ、音量の引き下げとフェードイン(§8.1)を適用する。どの環境で起きるかは実機確認(OPEN-002)。
- `stopped` の間も、パッチの編集(UI・エージェント)は可能。エンジンへの反映は開始時にまとめて行う(REQ-A-008)。
- 開始・再開のたびに出力はフェードインする(§8.1)。

## 4. 構成(責務と境界)
```
 ┌──────────────── ブラウザのタブ ─────────────────┐        ┌──── ローカルサーバー(Node.js, 127.0.0.1) ────┐
 │ [UI] ──コマンド──▶ [コマンド処理・パッチグラフ]  │◀─WS──▶│ [セッション中継] ◀── [共通コマンドAPI(WS/HTTP)] ◀── エージェント
 │   ▲   ◀─通知────  │ 検証・適用・履歴・リビジョン │        │        ▲                 ◀── [MCPアダプタ] ◀── MCPクライアント
 │   │               │        │ 差分(MessagePort)   │        │        │
 │   │               │        ▼                     │        │ [静的配信] [パッチファイル保存(専用フォルダ)]
 │ [自動保存]◀───────┘ [音声エンジン(AudioWorklet)]  │        └──────────────────────────────────────────────┘
 │ (ブラウザ内)          │ モジュール実行・リミッター │
 │ [Web MIDI]──event──▶  ▼                          │
 │                    スピーカー                     │
 └──────────────────────────────────────────────────┘
```
| 構成要素 | 責務 | 持つ状態 | 境界・データ流 |
|---|---|---|---|
| UI | 表示と入力。**状態を直接書き換えず、コマンドを発行する** | 表示用の一時状態のみ(選択、ドラッグ中等) | コマンド → コマンド処理、通知 ← コマンド処理 |
| コマンド処理・パッチグラフ(制御側) | **パッチの正本**。コマンドの検証・適用・履歴(取り消し)・リビジョン管理。UIとエージェントの操作を1本に直列化(DEC-105) | パッチグラフ(モジュール、ケーブル、パラメータ)、履歴、リビジョン | エンジンへ差分、UI/サーバーへ通知 |
| 音声エンジン(AudioWorklet) | モジュールの実行(#2仕様どおり)。出力段の保護。メーター値の算出 | 各モジュールの内部状態、PRNG状態 | 制御側とはMessagePort(F-021-015)。描画スレッドで動作(F-021-002) |
| 自動保存 | 作業中パッチのブラウザ内保存 | 最新のパッチJSON | データ契約 |
| ローカルサーバー | 静的配信、エージェント用APIの待受、タブへの中継、パッチファイルの保存、MCPアダプタ | 接続セッション、トークン、保存フォルダ | 127.0.0.1のみ。**パッチの正本は持たない**(タブへ中継する) |
| MCPアダプタ | 共通コマンドをMCPのツールとして公開する薄い変換層(DEC-002, OPEN-008) | なし | 共通コマンドAPIを呼ぶだけ |
| Web MIDI | MIDI入力をエンジンへ渡す | — | MOD-IO-002 の `event` 入力(COM-01) |

**タブがない場合**: エージェントの要求は「セッションなし」のエラーを返す(パッチの正本がタブ側にあるため)。保存済みパッチファイルの一覧・読出し(`patch.list`/`patch.read`)と、モジュール種別の列挙(`module.list_types`)のみ可能。

## 5. 音声エンジン
1. **処理モデル**: #2 COM-05/06 のとおり、全モジュールを単一の `fs` で1サンプルずつ同期実行し、ケーブルは1サンプル遅延。実装は128フレームのブロックで回すが、結果は1サンプル処理と一致させる(DEC-108)。
2. **フィードバック**: ケーブルの1サンプル遅延により、ループは常に定義される(COM-06)。評価順序に依存しない(REQ-F-011)。
3. **サンプルレート**: AudioContextの実レートを `fs` とする(DEC-107)。レートが変わる場合(デバイス変更)は全状態を再初期化する(COM-05)。
4. **ポリフォニー**: 1ケーブル最大16チャンネル(COM-08)。現行のMOD-IO-001は1チャンネル目のみを出力するため、**ポリ信号を出力でまとめる方法が未決(OPEN-011)**。各モジュールはチャンネルごとに独立に処理し、加算系は例外規則に従う。MOD-IO-002 のポリ割当(ボイス割当規則)は、#2の改訂タスクで定義する(**OPEN-004**。モノの動作は着手可)。
5. **決定性**: 同じパッチ・入力・`fs` で出力は再現する。乱数はCOM-11。検証にはオフライン描画(OfflineAudioContext相当、または同じエンジンコードの直接実行)を使う(REQ-NF-003)。
6. **パラメータ更新**: 制御側からの変更はメッセージで届き、次の処理ステップ(実装上は次のブロック先頭)から有効(COM-13)。ブロック境界への量子化は最大128フレームの遅れになる(§9の遅延測定に含める)。
7. **グラフ変更**: モジュール・ケーブルの追加削除は、ブロック境界で一括適用する。追加モジュールは初期状態(COM-10)から開始する。削除・切断時のクリック抑制は初期版では行わない(出力段のリミッターで保護。改善は後続)。

## 7. 外部操作インターフェース
1. **共通コマンドAPI**: コマンド・引数・返値・エラー・同期規則は [operation-contract.md](operation-contract.md) が正本。輸送はWebSocket(通知あり)を基本とし、同じコマンドをHTTPでも呼べる。
2. **MCPアダプタ**: 共通コマンドを1対1でツールとして公開する。独自の状態・独自の機能を持たない(REQ-A-007)。輸送方式はOPEN-008。
3. **MIDI**: Web MIDIでノート、ピッチベンド、CC、クロックを受け、MOD-IO-002 に渡す。メッセージのサンプル番号への割当は「受信した処理ブロックの先頭」とし、ブロック内は到着順(COM-07)。非対応ブラウザではMIDI機能を無効にし、その旨を状態で示す。

## 8. 安全・保護
### 8.1 出力音量・暴走時(DEC-004)
製品の出力保護は、MOD-IO-001 の**クリップより前の信号**に作用させる(DEC-110)。順序: MOD-IO-001 の音量・ミュート(クリップ前の値、±5 V=±1.0)→ 非有限値の検出と除去 → マスター音量 → リミッター → 最終クリップ(±1.0)→ デバイス。MOD-IO-001 の±1.0クリップと非有限値の0置換は、この最終段として扱う(**#2 の MOD-IO-001 の改訂が必要**。現行仕様のままでは後段のリミッターと検出が働かない)。
| 機構 | 内容 | 値の扱い |
|---|---|---|
| 非有限値の検出と除去 | 各モジュールがCOM-12で置換した回数をエンジンが集計して通知する。出力段でもNaN/∞を0に置換し、数える(DEC-112、REQ-S-006) | — |
| マスター音量 | 起動時は**低い既定値**から始める。パッチの読込・新規作成・置き換えを伴う取り消し/やり直し・緊急停止の解除・音声の開始/再開・サンプルレート変更による再初期化では **min(現在値, 既定値)** にしてフェードインする(音量を自動で上げない: DEC-111、REQ-S-003) | 既定値・フェード時間は**未決(OPEN-010)**。初期案: 既定−20 dB、フェード50 ms(未測定のため確定値としない) |
| エージェント上限 | エージェントが設定できるマスター音量の上限。上限の変更は人のUI操作のみ(REQ-S-004) | **未決(OPEN-014)**。初期案: 上限は人が最後に設定した値。読込等で上限は変わらない(DEC-111) |
| リミッター | 常時有効。出力が名目範囲[-1,1]を超えないよう利得を下げる(REQ-S-001)。範囲外・非有限の出力は仕様上未定義(F-021-003)のため必ず内側で止める | しきい値・時定数・方式は**未決(OPEN-010)** |
| 最終クリップ | リミッターの後に±1.0でハードクリップ(保険) | 固定 |
| 緊急停止 | `engine.panic`: マスターを即時ミュートし、全モジュールの内部状態を初期化(`reset()`)。パッチは保持。解除は人のUI操作のみ(REQ-S-002) | — |
自動ミュート(過大出力の継続で自動的に止める)は初期版では行わない(DEC-004で不採用)。

### 8.2 外部アクセス・認証境界
| 項目 | 設計 |

| スクリプト実行 | パッチやコマンドに任意コードを含めない(コード評価機能を持たない) |
