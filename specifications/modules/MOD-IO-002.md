# MOD-IO-002 MIDI-CV

## 1. 目的と範囲
- 目的: 外部から届くMIDIメッセージ(ノート、ピッチベンド、コントロールチェンジ、クロック)を、パッチ内のCV/ゲート信号(1 V/octのピッチ、ゲート、ベロシティ、ピッチホイール、モジュレーション、再トリガ、クロック)に変換する。1サンプルの処理は「そのサンプル時刻のMIDIメッセージを到着順に処理 → ノートスタック等の状態を更新 → 各出力を書く」。
- 含む: 単音(モノ)の最後に押したノート優先、レガート時はゲートを落とさない、ベロシティ、ピッチベンド、1つのCC、MIDIクロック(24PPQN)、受信チャンネル、移調、All Notes Off/All Sound Off。
- 含まない: ポリフォニー(複数ボイス割当)、MPE、チャンネル毎の別出力、START/STOP/CONTINUE、プログラムチェンジ、アフタータッチ、SysEx、MIDI出力(CV→MIDI)、MIDIデバイスの選択と外部エージェント接続(#3)。

## 3. ポート
| 名前 | 方向 | 型 | ch | 単位 | 範囲 | 更新周期 | 未接続時 |
|---|---|---|---|---|---|---|---|
| MIDI | in | event(MIDIメッセージ。COM-01の型にないので [X]) | 1 | メッセージ(ノートオン/オフ、ピッチベンド、CC、クロック。各メッセージはサンプル番号付き) | チャンネル1〜16、データバイト0〜127(ピッチベンドは0〜16383)。範囲外・未対応メッセージは無視 | そのサンプルに届いたメッセージを到着順に処理 | メッセージなし(状態は更新されず、出力は現在の保持値) |
| PITCH | out | pitch | 1 | V(1 V/oct) | (0..127 + transpose − 60)/12。transpose∈[−48,48]で −9.0〜+9.5833 | サンプル毎 | 出力は未接続でも通常どおり計算 |
| GATE | out | gate | 1 | V | 0 または 10 | サンプル毎 | 出力は未接続でも通常どおり計算 |
| VEL | out | cv | 1 | V | 0〜10 | サンプル毎 | 出力は未接続でも通常どおり計算 |
| PW | out | cv | 1 | V | −5〜+4.99939 | サンプル毎 | 出力は未接続でも通常どおり計算 |
| MOD | out | cv | 1 | V | 0〜10(`10·cc値/127`) | サンプル毎 | 出力は未接続でも通常どおり計算 |
| RTRG | out | trigger | 1 | V | 0 または 10(幅 `Nt=max(1,round(0.001·fs))` サンプル) | サンプル毎 | 出力は未接続でも通常どおり計算 |
| CLK | out | clock | 1 | V | 0 または 10(幅 `Nt` サンプル) | サンプル毎 | 出力は未接続でも通常どおり計算 |

- 「MIDI」入力はケーブルで接続するポートではなく、エンジンがMIDI入力(デバイス、エージェント)から渡すイベント列。「未接続」とは「そのサンプルにメッセージがない/MIDI入力が割り当てられていない」ことを指す。[X]
- 出力はモノ(1ch)のみ。ポリ出力は持たない(COM-08の初期方針)。

## 4. パラメータ
| 名前 | 単位 | 範囲 | 既定値 | 変調 | 更新タイミング | 補間 |
|---|---|---|---|---|---|---|
| channel | MIDIチャンネル(整数)。0=オムニ(全チャンネル受信) | 0〜16。範囲外はクランプ | 0 | なし | 次のステップ。値が変わると保持中のノートを全て解放(ゲートLow) | なし |
| transpose | 半音(整数) | −48〜+48。範囲外はクランプ、非整数は切り捨て | 0 | なし | 次のステップ | なし(PITCHが階段状に変わる) |
| cc_number | CC番号(整数) | 0〜127。範囲外はクランプ | 1(モジュレーションホイール) | なし | 次のステップ。変更しても `MOD` の現在値は新しい番号のCCが来るまで保持 | なし |

- CV入力を持たないため変調式はない。
- 乱数は使わない(`seed` なし)。

## 5. 内部状態と初期化・リセット
| 名前 | 型 | 初期値 | 意味 |
|---|---|---|---|
| stack | (note, vel)の列(最大128、末尾が最後に押したノート) | 空 | 押されているノート。同じノートの再ノートオンは既存を削除して末尾へ |
| cur_note | int または なし | なし | 最後に有効だったノート番号(ゲートが落ちた後も保持) |
| vel_v | float | 0.0 | VEL出力値(V) |
| pw_v | float | 0.0 | PW出力値(V) |
| mod_v | float | 0.0 | MOD出力値(V) |
| rtrg_cnt | int ≥ 0 | 0 | RTRGの残りサンプル数 |
| clk_cnt | int ≥ 0 | 0 | CLKの残りサンプル数 |
| last_channel | int | 生成時の `channel` | `channel` 変更検出用 |

- `cur_note=なし` のとき PITCH は0 V(C4)。
- `reset()`(COM-10): 全状態を初期値へ(スタック空、`cur_note=なし`、各出力値0、パルスカウンタ0、`last_channel=現在のchannel`)。パラメータは変えない。
- RESET入力ポートはない(該当なし。理由: MIDIのAll Notes Off等で代替し、音楽的リセットのポートを持たない)。

## 6. 振る舞い
サンプルレート依存: `Nt = max(1, round(0.001·fs))`(fs=48000で48、44100で44)。それ以外は `fs` に依存しない(メッセージの時刻がサンプル番号のため)。

メッセージ型(エンジンが渡す、サンプル `n` の列 `msgs[n]`):
```
note_on(ch, note, vel)    ch=1..16, note=0..127, vel=0..127
note_off(ch, note, vel)   vel は使わない
pitch_bend(ch, v14)       v14=0..16383(8192が中央)
cc(ch, num, val)          num=0..127, val=0..127
clock()                   0xF8、チャンネルなし
```
1サンプルの処理(入力を読む → 状態更新 → 出力):
```
// 0. channel変更の検出
if channel != last_channel: stack = []; last_channel = channel
// 1. メッセージを到着順に処理
for m in msgs[n]:
    if m is clock:  clk_cnt = Nt;  continue
    if not (1 <= m.ch <= 16):  continue                       // 無効は無視
    if channel != 0 and m.ch != channel:  continue            // 他チャンネルは無視
    switch m:
      note_on / note_off:
        if not (0<=note<=127 and 0<=vel<=127): continue
        if note_on and vel > 0:
            stack = [e for e in stack if e.note != note] + [(note, vel)]
            rtrg_cnt = Nt
        else:                                                  // note_off、またはvel=0のnote_on
            stack = [e for e in stack if e.note != note]
      pitch_bend:  if 0<=v14<=16383: pw_v = 5*(v14 - 8192)/8192
      cc:
        if not (0<=num<=127 and 0<=val<=127): continue
        if num == 120 or num == 123: stack = []                // All Sound Off / All Notes Off
        if num == cc_number: mod_v = 10*val/127
// 2. 現在ノートの決定
if stack is not empty:
    (cur_note, v) = stack[last];  vel_v = 10*v/127
// 3. 出力
PITCH = (cur_note is none) ? 0 : (cur_note + clamp(transpose,-48,48) - 60)/12
GATE  = (stack is not empty) ? 10 : 0
VEL = vel_v;  PW = pw_v;  MOD = mod_v
RTRG = (rtrg_cnt > 0) ? 10 : 0;  if rtrg_cnt > 0: rtrg_cnt -= 1      // 書いた後に減算
CLK  = (clk_cnt  > 0) ? 10 : 0;  if clk_cnt  > 0: clk_cnt  -= 1
```
- 同一サンプルの `clock` が複数あっても1パルスにまとまる。
- ノートオンのサンプルで PITCH、VEL、GATE、RTRG が同時に変わる(遅延なし)。接続先でピッチの整定を待ちたい場合の遅延はこのモジュールでは入れない。[A]
- レガート: 押下中に別のノートオンがあってもGATEは10 Vのまま。RTRGだけ新たにパルスが出る。
- 状態に乱数は使わず、同じメッセージ列から出力は決定的に定まる。

## 7. 共通規約との関係
- COM-03: `PITCH = (note + transpose − 60)/12`(0 V=C4=ノート60)。
- COM-04: GATE=10 V、RTRG/CLKはトリガ幅 `Nt`(1 ms)。入力側のシュミットはない(入力はイベント)。
- COM-05/06: 1サンプル=1ステップ、ケーブル遅延は接続時のみ。
- COM-07: 同一サンプルの複数イベントは**到着順**(MIDIメッセージに限る)。RESET入力がないため1 ms無視区間は採用しない。
- COM-08: モノ(1ch)のみ。
- COM-09: 「未接続」=メッセージなし。
- COM-10: `reset()` は全状態を初期化。
- COM-12: 数値入力(float)がないのでNaN/∞処理は不要。範囲外のデータバイトはメッセージ単位で無視する(§8)。
- COM-13: パラメータ範囲外はクランプ。COM-14: §9。
- 固有: MIDI入力型はCOM-01に無く、`event` を本仕様で追加した [X] (共通規約への指摘に記載)。

## 8. 異常入力・境界・数値安定性
- 無効メッセージ(チャンネル0または17以上、データバイトが0〜127の外、ピッチベンドが0〜16383の外)は**メッセージ全体を無視**し、状態を変えない。
- `channel≠0` のとき他チャンネルのメッセージは無視(ノートオフも含む)。このため、チャンネル設定変更後にノートが残らないよう、変更時にスタックを空にする(§6)。
- 同じノートが押されたまま再度ノートオンされた場合、スタックの順序を更新(末尾へ)し、RTRGを再発行する。
- 押されていないノートへのノートオフは無視する。
- スタックの最大長は128(ノート番号が重複しないため)。
- 移調で範囲外になるノート(例: 127+48)もPITCHは計算するだけで、クランプしない。範囲は ±12 V 内に収まる(最大+9.5833 V)。
- 同一サンプルでノートオフとノートオンが続く場合、全メッセージを処理した後の状態から出力するため、ゲートは落ちない(スタックが空でなければ10 Vのまま)。
- ノートが全て離された後も PITCH と VEL は最後の値を保持する(ゲートのみ0)。
- 数値: 浮動小数点は `10·v/127` 等の単純式のみ。0除算なし。

## 9. 保存・復元・版互換
- 保存対象: ①パラメータ(`channel`、`transpose`、`cc_number`)、②内部状態(`stack`(順序付き)、`cur_note`、`vel_v`、`pw_v`、`mod_v`、`rtrg_cnt`、`clk_cnt`、`last_channel`)、③PRNG状態: なし、④`spec_id=MOD-IO-002`、仕様版 `0.1`。
- 復元後は同じメッセージ列に対しビット同一の出力列を返す(TV-MOD-IO-002-13)。
- MIDIデバイス側の状態(接続中のデバイス、押下中のハードのキー)は本仕様の保存対象外。
- 版移行: 初版のため該当なし。

### 音質・時間精度に関する要件(機能再現とは別項)
- 本モジュールは波形を生成しないため、音質(エイリアシング等)の要件はない。
- 時間精度: MIDIメッセージの時刻はエンジンが付与するサンプル番号。MIDIデバイスの到着から時刻付与までの遅延・ジッタは本仕様の範囲外(#3)。モジュール内部では、メッセージのサンプル番号 `n` と、出力が変化するサンプル番号が一致すること(遅延0サンプル)。測定方法: TV-01のように `on` を n に与え、GATE/PITCH/VEL/RTRGが n で同時に変わることを確認する。

## 11. 未確認・保留事項
- [A→#3] 最後のノートを離したときに前のノートへ戻る規則、全て離した後のPITCH/VEL保持(S-07)。M003は「note-off時のpitch保持規則」を未確認としているため、独自に定めた。
- [A→#3] ベロシティ0のノートオンをノートオフ扱い、範囲外メッセージの無視(メッセージ全体)。
- [#3] MIDIメッセージへのサンプル番号付与(デバイス到着時刻→サンプル番号の規則、ジッタ、バッファ)。エージェント/外部制御からノートを送る場合の時刻の与え方。
- [#3] `event` 型(MIDI入力ポート)をCOM-01の信号型に追加するか。本仕様は「エンジンがイベント列を渡す」と抽象化。
- 保留: ポリフォニー(複数ボイス、Rotate/Reuse/Resetの割当モード。F-005-034)、MPE、START/STOP/CONTINUE、クロックの分周出力(CLK/N、F-005-033)、アフタータッチ、プログラムチェンジ、CC番号の複数出力。catalogが「MPE等は後続」とする。
- 保留: ピッチベンド幅(半音数)の扱い。M003のPWは−5〜+5 Vの電圧出力のみで、V/OCTには加算されない。幅の解釈は受け側(VCOのFM感度)に委ねる。
- DBに根拠が見つからず[A]にした主要項目: ノート優先の戻り規則、ベロシティ0の扱い、RTRG/CLKのパルス幅、チャンネル変更時のスタック消去、PW・VEL・MODの変換式の端点(0→−5 V、127→10 V)。
