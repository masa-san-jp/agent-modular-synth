# MOD-IO-001 オーディオ出力

## 1. 目的と範囲
- 目的: パッチ内の音声(V)をマスター出力としてまとめ、出力音量(`level`、`mute`)を掛けて、固定のフルスケール(FS)のデジタル値へ変換し、デバイス側の範囲 [−1, +1] に収める。過大入力(暴走)はこの段で必ず範囲内に制限し、クリップを知らせる。1サンプルの処理は「IN_L/IN_Rを読む → 音量(平滑)を更新 → スケールしてクリップ → DEV_L/DEV_R/CLIPを書く」。
- 含む: ステレオ入力(R未接続はLを複写)、線形の出力音量、ミュート、音量変化の平滑、フルスケール範囲へのハードクリップ、クリップ表示(CLIP出力とクリップ回数)。
- 含まない: 実機のD/A変換・出力インピーダンス・ヘッドホン出力の特性、デバイス選択・サンプルレート・ブロックサイズ(エンジン側)、ディザ・DCカット・ラウドネス計測・リミッタ(§11)。安全設計の方針(自動保護の要否、既定音量、最大音量)は#3の判断で、本仕様は機能としての範囲だけを定める。

## 3. ポート
| 名前 | 方向 | 型 | ch | 単位 | 範囲 | 更新周期 | 未接続時 |
|---|---|---|---|---|---|---|---|
| IN_L | in | audio | 1 | V | 任意の有限値(NaN/±∞は0 V扱い) | サンプル毎 | 0 V |
| IN_R | in | audio | 1 | V | 任意の有限値(NaN/±∞は0 V扱い) | サンプル毎 | normal=IN_L(同じサンプルのIN_Lの値) |
| DEV_L | out | audio | 1 | FS(デジタルのフルスケール。±1.0=±5 V、COM-02の例外 [X]) | −1.0〜+1.0(必ず範囲内) | サンプル毎 | 出力(デバイスへ渡す値)は常に計算する |
| DEV_R | out | audio | 1 | FS(同上) | −1.0〜+1.0(必ず範囲内) | サンプル毎 | 出力(デバイスへ渡す値)は常に計算する |
| CLIP | out | gate | 1 | V | 0 または 10 | サンプル毎 | 出力は未接続でも通常どおり計算 |

- DEV_L/DEV_Rは、パッチ内の他モジュールへ配線するためのポートではなく、エンジンがオーディオデバイスへ渡す値(シンク)である。パッチ上のケーブルで取り出す必要はない。[X]
- CLIPは「そのサンプルでDEV_LまたはDEV_Rが範囲を超えてクリップされたか」を示す。ポートとしてメーター等へ配線できる。
- ポートはモノ(1ch)。ポリ入力は1ch目のみ使う。[A] (COM-08の初期方針。ポリ入力の自動ミックスダウンは#3)

## 4. パラメータ
| 名前 | 単位 | 範囲 | 既定値 | 変調 | 更新タイミング | 補間 |
|---|---|---|---|---|---|---|
| level | 線形倍率(無単位) | 0〜2。有限の範囲外はクランプ。NaN/∞は既定1.0 | 1.0 | なし(CV入力を持たない) | 次のステップ | 時定数5 msの1次平滑(§6) |
| mute | 真偽(0/1) | 0 または 1(有限の0以外は1。NaN/∞は既定0) | 0 | なし | 次のステップ | 音量が0へ時定数5 msで平滑 |

- パラメータのNaN/∞は**既定値**(level=1.0, mute=0)として扱い、有限の範囲外値はクランプする(COM-12/13)。例: `level=+∞` は2でなく1.0、`level=3` は2。以下 `level_e = finite(level) ? clamp(level,0,2) : 1.0`、`mute_e = finite(mute) ? (mute != 0) : 0` とする。
- CV入力を持たないため、CV感度(COM-18)はない。
- `level` の目安: 1.0=0 dB、0.5≒−6.02 dB、2.0≒+6.02 dB。線形倍率で保持し、dB表示はUI(#3)の責務。
- 固定の定数(パラメータではない): フルスケール電圧 `VFS = 5 V`、クリップ範囲 ±1.0、平滑時定数 `τ = 0.005 s`。

## 5. 内部状態と初期化・リセット
| 名前 | 型 | 初期値 | 意味 |
|---|---|---|---|
| g | float | `mute_e ? 0 : level_e`(生成時/reset()時の**現在のパラメータ**から決める。§4の整形後の値) | 平滑後の音量(倍率) |
| clip_count | uint32(飽和加算) | 0 | クリップが起きたサンプルの累計(診断用。状態読出しで取得) |

- リセットの種類(COM-10): `reset()` の**全体リセット**のみ。位相・音楽的リセットはない。
- `reset()`(COM-10): `g ← (mute_e ? 0 : level_e)`(現在のパラメータの目標値。リセット時に音量が滑らかに動かないように)、`clip_count ← 0`。パラメータは変えない。
- RESET入力ポートはない(該当なし。理由: 音楽的リセットの概念がない)。
- 乱数は使わない。

## 6. 振る舞い
サンプルレート依存の係数:
```
a = 1 - exp(-1 / (0.005 * fs))      // fs=48000で 0.0041579982
```
1サンプルの処理(入力を読む → 状態更新 → 出力):
```
// 0. 入力の読出し。NaN/±∞は0 V (COM-12)
l = finite(IN_L) ? IN_L : 0
r = IN_R_connected ? (finite(IN_R) ? IN_R : 0) : l       // 未接続はnormal=IN_L(IN_Lの整形後の値)
// 1. 音量の平滑 (毎サンプル。目標値はこのステップ開始時のパラメータ)
target = mute_e ? 0 : level_e                              // level_e, mute_e: §4(NaN/∞は既定値、有限の範囲外はクランプ)
g = g + a * (target - g)
// 2. スケールとクリップ
vl = g * l / 5;   vr = g * r / 5                          // FS値(クリップ前)
clipped = (abs(vl) > 1) || (abs(vr) > 1)                  // ちょうど±1.0はクリップではない
DEV_L = clamp(vl, -1, +1);  DEV_R = clamp(vr, -1, +1)
CLIP  = clipped ? 10 : 0
if clipped: clip_count = min(clip_count + 1, 4294967295)
```
- 音量変化の閉形式: 目標 `T` へ向かうとき、変化前の `g0` から `k` サンプル後(最初のステップを k=1)の `g = T + (g0 − T)·(1−a)^k`。`mute=1` へ切替えて(g0=1)から `k=240` で `g = (1−a)^240 = e^−1 = 0.3678794`。
- 平滑は音量のみで、信号には遅延を加えない(DEVはそのサンプルのINから出る)。
- DCカット、ディザ、補間は行わない。入力のDC成分はそのまま出る。

## 7. 共通規約との関係
- COM-02: 入力は任意の有限値を許容する(§6)。「内部で黙って切り捨てない」方針に対し、デバイス境界であるここだけは範囲外を制限する。制限は黙って行わず、CLIPとclip_countで知らせる。
- COM-05/06: 1サンプル=1ステップ。単体検証は `x[n]→y[n]`。
- COM-09: IN_Rの未接続は `normal=IN_L`。IN_Lの未接続は0 V。
- COM-10: `reset()` は `g` を目標値へ、`clip_count` を0へ。
- COM-12: 入力のNaN/∞は0 V。パラメータのNaN/∞は既定値。出力は常に有限で ±1.0 以内。
- COM-13: パラメータ範囲外はクランプ。変調はなし。
- COM-14: §9。
- 固有: DEV_L/DEV_Rの単位FSは、COM-02の「1.0=1 V」の例外([X])。

## 8. 異常入力・境界・数値安定性
- NaN/±∞入力は0 V扱い(IN_Rが接続されていてNaNなら、R側は0 Vで、Lの複写にはならない)。
- 暴走(大きな有限値、例 ±1e30 V): `g·l/5` は有限のまま(float32で overflow しうる規模でもクランプが±1.0に収める。オーバーフローで±∞になっても `clamp` で ±1.0)、CLIP=10、`clip_count` 加算。出力にNaNは出ない。
- 継続的なクリップ(例: ±5 V超の方形波)は、サンプルごとにCLIP=10(連続時は10 V連続)、`clip_count` が増える。自動でmuteや音量低下は**しない**(自動保護は#3の方針判断。§11)。
- `level` 範囲外: 負は0、2超は2にクランプ。`mute` は有限の0以外を1とする。`level`/`mute` がNaN/∞のときは既定値(1.0 / 0)(TV-05 (c)(d))。
- `level=2`、入力±5 Vで FS値=±2.0 → ±1.0にクリップ(CLIP=10)。`level=1` で入力が ±5 V ちょうどなら FS値=±1.0 でクリップではない(`abs(v) > 1` が条件)。
- 無信号(0 V)ならDEV=0。`level=0` またはミュート完了後は、有限入力に対しDEV≒0(平滑の残りが指数的に減る)。
- 数値: `exp` は `fs>0` で安全。`fs` を変更する場合は全状態を再初期化(COM-05)する(この仕様では `g` が目標値に戻る)。
- ハードクリップの音質への影響(高調波、エイリアシング)は§10の別項。

## 9. 保存・復元・版互換
- 保存対象: ①パラメータ(`level`、`mute`)、②内部状態(`g`、`clip_count`)、③PRNG状態: なし(乱数を使わない)、④`spec_id=MOD-IO-001`、仕様版 `0.1`。
- 復元後は同じ入力列に対しビット同一の出力列を返す(TV-MOD-IO-001-10)。
- 版移行: 初版のため該当なし。将来、保護機能(リミッタ等)を足す場合は、旧データは「保護なし」として読み込む。

### 音質に関する要件(機能再現とは別項)
- ハードクリップは高調波とエイリアシング(折り返し歪み)を生む。本仕様はオーバーサンプリングやアンチエイリアスを持たない。クリップを起こさない範囲(`abs(V·g/5) ≤ 1`)では信号は線形で、歪みは生じない(DEV = g·V/5 が厳密に成り立つ)。
- 測定方法(クリップ域の歪み): 1 kHz(48サンプル周期の整数周期)、振幅8 V、level=1.0、窓幅8192サンプル(整数周期にならない場合はHann窓)で DEV_L のスペクトルを取り、基音と高調波(3次、5次…)およびエイリアス成分(`fs` 折り返し)のレベルを記録する。数値目標は根拠がないため固定しない(測定値の記録に留める)。
- 音量変化のクリック: 平滑(τ=5 ms)により、`mute` と `level` の階段変化が信号に不連続を作らないこと。測定方法: 1 kHz正弦波4 Vを入れて `mute` を切替え、DEV_Lの隣接サンプル差の最大値が、平滑前の階段変化(最大0.8)より小さいこと(定性要件。数値は固定しない)。
