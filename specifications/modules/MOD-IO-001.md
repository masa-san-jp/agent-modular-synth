# MOD-IO-001 オーディオ出力

## 1. 目的と範囲
- 目的: パッチ内の音声(V)をマスター出力としてまとめ、出力音量(`level`、`mute`)を掛けて、固定のフルスケール(FS)のデジタル値へ変換する。入力がポリのときは全チャンネルを加算する(DEC-007)。出す値は2種類ある。**クリップ前の値**(`PRE_L`/`PRE_R`。製品の出力保護への入力: DEC-110)と、それを ±1.0 にハードクリップした**参照出力**(`DEV_L`/`DEV_R`)。`PRE` が ±1.0 を超えたことは `CLIP` と `clip_count` で知らせる。1サンプルの処理は「IN_L/IN_Rを読む(ポリは加算)→ 音量(平滑)を更新 → スケール → PRE_L/PRE_R、DEV_L/DEV_R、CLIPを書く」。
- 含む: ステレオ入力(R未接続はLを複写)、ポリ入力の加算、線形の出力音量、ミュート、音量変化の平滑、クリップ前の値の出力、フルスケール範囲へのハードクリップ(参照出力)、過大の表示(CLIP出力と回数)。
- 含まない: 製品の出力保護(非有限値の検出と除去、マスター音量、リミッター、最終クリップ、緊急停止、起動時の低音量とフェードイン。[product-spec](../synthesizer/product-spec.md) §8.1 が定め、本モジュールの `PRE_L`/`PRE_R` の後段に置かれる)、実機のD/A変換・出力インピーダンス・ヘッドホン出力の特性、デバイス選択・サンプルレート・ブロックサイズ(エンジン側)、ディザ・DCカット・ラウドネス計測、ポリ入力の正規化(声数で割る処理)・パン。

## 3. ポート
| 名前 | 方向 | 型 | ch | 単位 | 範囲 | 更新周期 | 未接続時 |
|---|---|---|---|---|---|---|---|
| IN_L | in | audio | 1〜16(全チャンネルを加算) | V | 任意の有限値(NaN/±∞は0 V扱い) | サンプル毎 | 0 V |
| IN_R | in | audio | 1〜16(全チャンネルを加算) | V | 任意の有限値(NaN/±∞は0 V扱い) | サンプル毎 | normal=IN_L(同じサンプルのIN_Lの全チャンネルの和) |
| PRE_L | out | audio | 1 | FS(デジタルのフルスケール。±1.0=±5 V、COM-02の例外 [X]) | −100〜+100(±1.0でクリップしない。常に有限) | サンプル毎 | 配線不可。常に計算する(製品の出力保護への入力) |
| PRE_R | out | audio | 1 | FS(同上) | −100〜+100(同上) | サンプル毎 | 配線不可。常に計算する(製品の出力保護への入力) |
| DEV_L | out | audio | 1 | FS(同上) | −1.0〜+1.0(必ず範囲内) | サンプル毎 | 配線不可。常に計算する(参照出力) |
| DEV_R | out | audio | 1 | FS(同上) | −1.0〜+1.0(必ず範囲内) | サンプル毎 | 配線不可。常に計算する(参照出力) |
| CLIP | out | gate | 1 | V | 0 または 10 | サンプル毎 | 出力は未接続でも通常どおり計算 |

- **PRE_L/PRE_R**(0.2で追加): 音量・ミュートを掛けた後、クリップする前の値。パッチ内の他モジュールへ配線するポートではなく、エンジンが**製品の出力保護**へ渡す値である(DEC-110)。順序は「PRE → 非有限値の検出と除去 → マスター音量 → リミッター → 最終クリップ(±1.0)→ デバイス」(product-spec §8.1)。[X]
- **DEV_L/DEV_R**: `DEV = clamp(PRE, −1, +1)`。出力保護の最終クリップと同じ写像である。位置づけは**参照出力**で、(1) 出力保護を持たない構成(単体検証、オフラインの参照実行)でデバイスへ渡す値、(2) 「マスター音量 0 dB・リミッターなし」のときに製品がデバイスへ渡す値と一致する値、を与える。製品では、エンジンは `DEV` をデバイスへ渡さない(渡すのは `PRE` を出力保護に通した値)。配線不可。[X]
- **CLIP**: 「そのサンプルで `PRE_L` または `PRE_R` の絶対値が 1.0 を超えたか」(= `DEV` がクリップされたか)を示す。ポートとしてメーター等へ配線できる。製品では「リミッターより前で過大」の表示で、最終クリップの発生とは別(§6、S-12)。パルスは1サンプル単位のまま出し、保持はしない(UI表示の保持は1秒: DEC-011)。
- 入力はポリ(最大16チャンネル)を受け、チャンネルを加算して1チャンネルにまとめる(DEC-007、§6、§7)。出力はすべて1チャンネル。

## 4. パラメータ
| 名前 | 単位 | 範囲 | 既定値 | 変調 | 更新タイミング | 補間 |
|---|---|---|---|---|---|---|
| level | 線形倍率(無単位) | 0〜2。有限の範囲外はクランプ。NaN/∞は既定1.0 | 1.0 | なし(CV入力を持たない) | 次のステップ | 時定数5 msの1次平滑(§6) |
| mute | 真偽(0/1) | 0 または 1(有限の0以外は1。NaN/∞は既定0) | 0 | なし | 次のステップ | 音量が0へ時定数5 msで平滑 |

- パラメータのNaN/∞は**既定値**(level=1.0, mute=0)として扱い、有限の範囲外値はクランプする(COM-12/13)。例: `level=+∞` は2でなく1.0、`level=3` は2。以下 `level_e = finite(level) ? clamp(level,0,2) : 1.0`、`mute_e = finite(mute) ? (mute != 0) : 0` とする。
- CV入力を持たないため、CV感度(COM-18)はない。
- `level` の目安: 1.0=0 dB、0.5≒−6.02 dB、2.0≒+6.02 dB。線形倍率で保持し、dB表示はUI(#3)の責務。
- 固定の定数(パラメータではない): フルスケール電圧 `VFS = 5 V`、クリップ範囲 ±1.0、平滑時定数 `τ = 0.005 s`、`PRE` の飽和値 `PRE_MAX = 100`(S-15)。
- 0.2 でパラメータの追加・意味の変更はない(ポリ加算と `PRE` 出力のためのパラメータは持たない)。

## 5. 内部状態と初期化・リセット
| 名前 | 型 | 初期値 | 意味 |
|---|---|---|---|
| g | float | `mute_e ? 0 : level_e`(生成時/reset()時の**現在のパラメータ**から決める。§4の整形後の値) | 平滑後の音量(倍率) |
| clip_count | uint32(飽和加算) | 0 | `PRE_L` または `PRE_R` の絶対値が 1.0 を超えたサンプルの累計(診断用。状態読出しで取得)。製品の `output.clip_count`(最終クリップの回数)とは別の値(§6) |
| nonfinite_count | 非負整数(飽和加算。上限は 2³²−1 以上) | 0 | COM-12 の置換カウンタ。入力の NaN/±∞ を 0 V として扱った回数(1ポート・1チャンネル・1サンプルにつき1)。診断値で、保存の対象外(§8、§9) |

- **状態はエンジン(チャンネル)ごとには持たない**。本モジュールはチャンネルを1つにまとめるモジュール(COM-08 の例外、§7)で、内部エンジンは常に1つ。`g`・`clip_count`・`nonfinite_count` はモジュールに1組だけで、入力のチャンネル数が変わっても(接続の変更)状態は変わらない(増減するエンジンがない)。
- リセットの種類(COM-10): `reset()` の**全体リセット**のみ。位相・音楽的リセットはない。
- `reset()`(COM-10): `g ← (mute_e ? 0 : level_e)`(現在のパラメータの目標値。リセット時に音量が滑らかに動かないように)、`clip_count ← 0`、`nonfinite_count ← 0`。パラメータは変えない。
- RESET入力ポートはない(該当なし。理由: 音楽的リセットの概念がない)。
- 乱数は使わない(エンジンごとのseedの規則 COM-08/COM-11 は該当しない)。

## 6. 振る舞い
サンプルレート依存の係数:
```
a = 1 - exp(-1 / (0.005 * fs))      // fs=48000で 0.0041579982
```
1サンプルの処理(入力を読む → 状態更新 → 出力):
```
// 0. 入力の読出しとポリの加算。NaN/±∞のチャンネルは0 Vとして扱い、1つにつき nonfinite_count を1増やす (COM-12)
sum(P):                                                    // P: 接続された入力ポート。NP = Pのチャンネル数(1〜16)
  s = 0                                                    // 倍精度
  for c = 0 .. NP-1:                                       // チャンネル番号の昇順に加算(加算順を固定)
    if finite(P[c]): s = s + P[c]
    else:            nonfinite_count = min(nonfinite_count + 1, 上限)
  return s
l = IN_L_connected ? sum(IN_L) : 0
r = IN_R_connected ? sum(IN_R) : l                         // 未接続はnormal=IN_L(IN_Lの加算後の値。IN_Lを数え直さない)
// 1. 音量の平滑 (毎サンプル。目標値はこのステップ開始時のパラメータ)
target = mute_e ? 0 : level_e                              // level_e, mute_e: §4(NaN/∞は既定値、有限の範囲外はクランプ)
g = g + a * (target - g)
// 2. スケール → クリップ前の値
PRE_L = clamp(g * l / 5, -100, +100)                       // FS値。±1.0ではクリップしない。±PRE_MAXで飽和 (S-15)
PRE_R = clamp(g * r / 5, -100, +100)
// 3. 参照出力(最終クリップと同じ写像)と過大の表示
clipped = (abs(PRE_L) > 1) || (abs(PRE_R) > 1)             // ちょうど±1.0は過大ではない
DEV_L = clamp(PRE_L, -1, +1);  DEV_R = clamp(PRE_R, -1, +1)
CLIP  = clipped ? 10 : 0
if clipped: clip_count = min(clip_count + 1, 4294967295)
```
- **モノの入力では 0.1 と同じ値**: `DEV_L`/`DEV_R`/`CLIP`/`clip_count` の式は 0.1 と同じ(0.1 の `vl`/`vr` が `PRE_L`/`PRE_R` になった)。0.2 の違いは、(1) `PRE_L`/`PRE_R` を出力として出すこと、(2) 入力がポリのとき全チャンネルを加算すること、(3) `nonfinite_count` を数えること、(4) `PRE` の ±100 での飽和(`DEV`・`CLIP` には影響しない)。
- **ポリ入力の加算**(DEC-007): `IN_L`、`IN_R` はそれぞれ自分のチャンネル数で独立に加算する(`IN_L` が4チャンネル、`IN_R` が2チャンネルでもよい。相手のチャンネル数に合わせた複写や補完はしない)。モノの入力は1チャンネルの和で、値はそのまま。`IN_R` 未接続のときは、`IN_L` がポリでもモノでも `r = l`(`IN_L` の全チャンネルの和)。加算は倍精度で、チャンネル番号の昇順に行う(浮動小数点の加算は順序で結果が変わりうるため固定する)。
- **正規化はしない**(S-14): 和をチャンネル数で割らない。各 ±5 V の16声が同相で重なると和は ±80 V、`PRE` は ±16 FS(+24 dBFS)になる。この過大は `level`(パッチのパラメータ)と、後段のマスター音量・リミッター(product-spec §8.1)で扱う。`DEV`(参照出力)は ±1.0 にクリップされ、`CLIP`=10 になる。
- **製品の出力保護との関係**(DEC-110): 製品でデバイスへ渡す値は `最終クリップ(リミッター(マスター音量(非有限値の除去(PRE))))`。`PRE` は常に有限なので、通常の動作では後段の「非有限値の検出と除去」に非有限値は届かない(入力の非有限値は本モジュールが 0 V にして `nonfinite_count` に数え、エンジンが各モジュールの分として集計する: DEC-112)。後段の検出は、実装の不具合や試験用の注入に対する保険として残る。
- **`CLIP`・`clip_count` と製品の `output.clip_count` の関係**: 本モジュールの `CLIP`/`clip_count` は「`PRE` が ±1.0 を超えたサンプル」(マスター音量とリミッターの**前**)。操作契約 CMD-21 の `output.clip_count` は「最終クリップ(リミッターの**後**)が働いたサンプル」で、出力保護の段が数える。両者は別の計数で、一般には一致しない(例: `PRE`=2.0 が続くとき、本モジュールの `clip_count` は毎サンプル増えるが、マスター音量 −20 dB なら最終クリップは働かず `output.clip_count` は増えない)。一致するのは、マスター音量 0 dB・リミッターなしの構成(このとき最終クリップの入力が `PRE` に等しい)だけである。
- 音量変化の閉形式: 目標 `T` へ向かうとき、変化前の `g0` から `k` サンプル後(最初のステップを k=1)の `g = T + (g0 − T)·(1−a)^k`。`mute=1` へ切替えて(g0=1)から `k=240` で `g = (1−a)^240 = e^−1 = 0.3678794`。
- 平滑は音量のみで、信号には遅延を加えない(PRE・DEVはそのサンプルのINから出る)。
- DCカット、ディザ、補間は行わない。入力のDC成分はそのまま出る。

## 7. 共通規約との関係
- COM-02: 入力は任意の有限値を許容する(§6)。`PRE_L`/`PRE_R` は ±1.0 で切り捨てず、後段のリミッターへ過大な値のまま渡す(±100 の飽和は規約外の入力でのみ働く: S-15)。`DEV_L`/`DEV_R` はデバイス境界の写像として ±1.0 に制限する。制限は黙って行わず、CLIPとclip_countで知らせる。`PRE`/`DEV` の単位FSは、COM-02の「1.0=1 V」の例外([X]、COM-02(6))。出力の「±12 V を超えない」(COM-02(3))は電圧のポートの規則で、FS値の `PRE` には ±100 FS の上限を別に定める。
- COM-05/06: 1サンプル=1ステップ。単体検証は `x[n]→y[n]`。加算は倍精度で行う(§6)。
- **COM-08(ポリフォニー)— チャンネルをまとめるモジュールの例外**: 本モジュールは COM-08 の「チャンネルをまとめるモジュール(オーディオ出力等)」に当たり、次のとおり例外を定める。
  - **主入力と副入力**: `IN_L` と `IN_R` はどちらも「まとめる入力」で、エンジン数 `N` を決める主入力ではない。**副入力はない**(CV・ゲート・トリガ入力を持たない)。そのため「1チャンネルなら全エンジンへコピー」「不足チャンネルは 0 V」の副入力の規則は適用する対象がない。
  - **エンジン数**: 入力のチャンネル数によらず**常に1**。チャンネルごとに同じ式を適用するのではなく、各入力の全チャンネルを**加算**してから、モノの式(§6)を1回だけ適用する。したがって「チャンネル c の出力が、同じ入力をモノで与えたときと一致」は成り立たない。代わりに、`PRE` が飽和しない範囲で「ポリ入力の `PRE` = 各チャンネルを単独のモノ入力として与えたときの `PRE` の和」が成り立つ(線形性。TV-12)。`DEV`・`CLIP` は和に対して決まり、チャンネルごとには決まらない(チャンネル間の相互作用を持つ)。
  - **出力のチャンネル数**: `PRE_L`/`PRE_R`/`DEV_L`/`DEV_R`/`CLIP` はすべて1チャンネル(COM-08 の「出力は `N` チャンネル」の例外)。
  - **加算の規則**: `IN_L`、`IN_R` は自分のチャンネル数で独立に加算する(MOD-MIX-001 の加算系の例外と同じく、相手に合わせたコピーをしない)。`IN_R` 未接続の `normal` は `IN_L` の和。
  - **状態・パラメータ・乱数**: 状態はモジュールに1組(§5)。パラメータは1組(COM-08 の「全エンジンで共有」と同じ)。乱数は使わない。
- COM-09: IN_Rの未接続は `normal=IN_L`(ポリのときは全チャンネルの和)。IN_Lの未接続は0 V。
- COM-10: `reset()` は `g` を目標値へ、`clip_count` と `nonfinite_count` を0へ。
- COM-12: 入力のNaN/∞は0 V(チャンネルごと)で、置換カウンタ `nonfinite_count` に数える(§8)。パラメータのNaN/∞は既定値(数えない)。出力は常に有限で、`PRE` は ±100 以内、`DEV` は ±1.0 以内。
- COM-13: パラメータ範囲外はクランプ。変調はなし。
- COM-14: §9。

## 8. 異常入力・境界・数値安定性
- NaN/±∞入力は0 V扱い(IN_Rが接続されていてNaNなら、R側は0 Vで、Lの複写にはならない)。ポリ入力では**チャンネルごと**に判定し、非有限のチャンネルだけを 0 V にして残りを加算する(1チャンネルの NaN が和全体を消さない)。
- **置換カウンタ**(COM-12、DEC-112): `nonfinite_count` は、接続された `IN_L`・`IN_R` の各チャンネルの NaN/±∞ を 0 V にしたとき、1チャンネル・1サンプルにつき1増やす。`IN_R` 未接続で `IN_L` に NaN があるときは `IN_L` の分だけを数える(`normal` の複写を二重に数えない)。出力の置換は起こらない(`PRE`・`DEV`・`CLIP` は構成上つねに有限)ので、出力の分は常に0。パラメータのNaN/∞は数えない。出力値には影響しない(TV-07、TV-16)。
- 暴走(大きな有限値、例 ±1e30 V): `PRE` は ±100 で飽和し、`DEV` は ±1.0、CLIP=10、`clip_count` 加算。加算と `g·l/5` は倍精度で計算するので、float32 の有限値16チャンネルの和でも桁あふれせず、±∞・NaN は出ない(TV-07 (c)、TV-16 (b))。
- 継続的な過大(例: ±5 V超の方形波、多声の和)は、サンプルごとにCLIP=10(連続時は10 V連続)、`clip_count` が増える。本モジュールは自動でmuteや音量低下を**しない**(製品でも自動ミュートは行わない: DEC-004。過大な `PRE` は後段のリミッターが下げる)。
- ポリの和の過大: 16チャンネル × ±12 V、`level=2` で `PRE` = ±76.8 FS(規約内の入力の最大。飽和しない)。逆相のチャンネルは打ち消し合う(+5 V と −5 V の和は 0)。和がちょうど ±5 V(`PRE` = ±1.0)は過大ではない(TV-15)。
- `level` 範囲外: 負は0、2超は2にクランプ。`mute` は有限の0以外を1とする。`level`/`mute` がNaN/∞のときは既定値(1.0 / 0)(TV-05 (c)(d))。
- `level=2`、入力±5 Vで `PRE`=±2.0 → `DEV` は ±1.0(CLIP=10)。`level=1` で入力が ±5 V ちょうどなら `PRE`=±1.0 で過大ではない(`abs(PRE) > 1` が条件)。
- 無信号(0 V)ならPRE=DEV=0。`level=0` またはミュート完了後は、有限入力に対しPRE≒0(平滑の残りが指数的に減る)。
- 数値: `exp` は `fs>0` で安全。`fs` を変更する場合は全状態を再初期化(COM-05)する(この仕様では `g` が目標値に戻る)。
- ハードクリップの音質への影響(高調波、エイリアシング)は§10の別項。
- `CLIP` と `clip_count` の判定に使う `PRE` は、出力ポートへ書く float32 の値。(2026-11-20、実装で補った解釈を明文化)

## 9. 保存・復元・版互換
- 保存対象: ①パラメータ(`level`、`mute`)、②内部状態(`g`、`clip_count`)、③PRNG状態: なし(乱数を使わない)、④`spec_id=MOD-IO-001`、仕様版 `0.2`。`nonfinite_count` は診断値で保存しない(COM-12。復元後は0から数える)。
- 復元後は同じ入力列に対しビット同一の出力列を返す(TV-MOD-IO-001-10、TV-MOD-IO-001-18)。
- **0.2 での変更点**:
  1. クリップ前の内部出力 `PRE_L`/`PRE_R` を追加(配線不可。製品の出力保護への入力: DEC-110)。`DEV_L`/`DEV_R` は「`PRE` を ±1.0 でクリップした参照出力(最終クリップと同じ写像)」と位置づけを改めた。`DEV` の値の式は変えていない。
  2. `CLIP`・`clip_count` の定義を「`PRE` が ±1.0 を超えたサンプル」と明文化(式は 0.1 と同じ)。製品の `output.clip_count`(最終クリップ)とは別の計数であることを明記。
  3. **挙動変更**: 入力がポリのとき全チャンネルを加算する(0.1 は1チャンネル目のみ: DEC-007)。`IN_R` 未接続の `normal` は `IN_L` の全チャンネルの和。
  4. COM-12 の置換カウンタ `nonfinite_count` を追加。`PRE` を ±100 FS で飽和(S-15)。
  5. COM-08 の例外(チャンネルをまとめるモジュール)を §7 に明記。ポリと `PRE` の検証例(TV-11〜18)を追加。
- **保存データへの影響(移行)**: **移行不要**。パラメータの追加・削除・意味の変更はない(`level`、`mute` は同じ意味・範囲・既定値)。内部状態 `g`、`clip_count` の意味と式も同じ。0.1 で保存したパッチ・スナップショットはそのまま読める。
- **音の変化に関する注意**(データの移行ではない): モノのケーブルだけをつないだパッチは 0.1 と同じ値を出す。`IN_L`/`IN_R` にポリのケーブルをつないだパッチは、0.1 では1チャンネル目だけが出ていたが、0.2 では全チャンネルの和が出る(音量が上がりうる)。
- 将来、本モジュールにパラメータを足す場合は、旧データを既定値で読み込む。

### 音質に関する要件(機能再現とは別項)
- `DEV`(参照出力)のハードクリップは高調波とエイリアシング(折り返し歪み)を生む。本仕様はオーバーサンプリングやアンチエイリアスを持たない。過大でない範囲(`abs(PRE) ≤ 1`)では信号は線形で、歪みは生じない(DEV = PRE = g·V/5 が厳密に成り立つ)。`PRE` は ±100 の飽和に達しない限り、常に線形(歪みなし)。
- 製品でデバイスへ渡す値の歪み(リミッターと最終クリップによるもの)は、本仕様でなく検証計画 VER-NF-007h が測る。
- 測定方法(`DEV` のクリップ域の歪み): 1 kHz(48サンプル周期の整数周期)、振幅8 V、level=1.0、窓幅8192サンプル(整数周期にならない場合はHann窓)で DEV_L のスペクトルを取り、基音と高調波(3次、5次…)およびエイリアス成分(`fs` 折り返し)のレベルを記録する。数値目標は根拠がないため固定しない(測定値の記録に留める)。
- 音量変化のクリック: 平滑(τ=5 ms)により、`mute` と `level` の階段変化が信号に不連続を作らないこと。測定方法: 1 kHz正弦波4 Vを入れて `mute` を切替え、PRE_L(=DEV_L)の隣接サンプル差の最大値が、平滑前の階段変化(最大0.8)より小さいこと(定性要件。数値は固定しない)。
