# 共通信号・接続・時間・状態規約(COM)

版: 0.3 / 作成: 2026-11-13 / 状態: 初期版(各モジュール仕様 `*.md` の正本。ここを変更したら全モジュール仕様の整合を再検査する)

本書は**機能の再現**のための規約であり、原機の完全な音響再現は保証しない。記述は次の3種を区別する。

| 記号 | 意味 |
|---|---|
| **[R]** | 原著(公開資料)の事実。根拠はリファレンスDBのID(`F-…`/`REF-…`/`I…`/`M…`)で示す。二次資料のみの場合は確度を併記 |
| **[A]** | 設計上の仮定・選択。資料が一意に定めない部分をこの仕様で決めたもの。#3で見直しうる |
| **[X]** | こちらの抽象化(複数機種の共通化、ハード電圧のデジタル値への写像) |

リファレンスDB: 拡張DB `references/db/`(事実ID `F-…`)、精査済みDB `references/`(`I…`/`M…`)。食い違う場合は精査済みDBを優先する([crosswalk](../../references/db/docs/crosswalk.md))。

## COM-01 信号型

全てのポートは「電圧相当の実数列」を運ぶ。型は意味のタグであり、接続の可否を制限しない。

| 型 | 意味 | 典型範囲 [R/A] |
|---|---|---|
| `audio` | 可聴帯域の信号 | ±5 V(10 Vpp) |
| `cv` | 制御電圧(連続値) | 単極 0〜10 V、双極 ±5 V |
| `pitch` | 1 V/oct の `cv` | COM-03 |
| `gate` | 区間でhighを保つ論理信号 | 0 V / 10 V |
| `trigger` | 立ち上がり時刻だけが意味を持つパルス | 0 V / 10 V、幅 1 ms |
| `clock` | 周期トリガ。`trigger` と同じ扱いで、周期が意味を持つ | 0 V / 10 V |
| `event` | 値の列でなく**メッセージ**(MIDIのノートオン/オフ、CC等)。ケーブルで運ぶ信号ではなく、IO境界のモジュール(例: MOD-IO-002)が受け取る。[X] | メッセージ型(各仕様が定義) |

- [R] どの出力も任意の入力に接続でき、ケーブルが運べる信号の種類に制約はない(F-005-002、F-001-009)。型違い接続は許可し、UIが警告を出すかは#3で決める。[A]
- [R] 各種の典型値はメーカー資料でも「厳密な標準でなく慣習の近似」とされる(F-005-015、F-001-039)。本書の値は**この製品内の規約**である。[A]
- 二次資料では、実機Eurorackのgate/trigger慣習は0〜5 V、単極CVは0〜8 V(F-005-046/047、F-001-039。確度low〜medium)。VCV Rackの典型(F-005-009、F-005-011。確度high)を採用し、実機との差は互換変換モジュール(後続)で扱う。[A]

## COM-02 値表現と範囲

1. ポート値は **32bit浮動小数点**で、単位は **V(ボルト相当)**。デジタル値1.0 = 1 V。[X]
2. 入力は任意の有限値を受け付ける。モジュールは各仕様で定めた式に従う。範囲外の値を黙って切り捨てない(ハードクリップより範囲外許容が推奨される: F-005-010)。[R→A]
3. 各モジュールが**生成する**出力は ±12 V を超えない設計とする([R] F-005-010: Eurorack電源±12 Vを超える電圧は生成すべきでない)。超えうる処理(利得、加算)は仕様ごとに出力範囲を明記し、必要なら ±12 V でクリップする。[A]
4. NaN・±∞は COM-12 に従う。
5. **クリップは出力段で行う**。入力を内部で黙って切り捨てない((2))が、モジュールが生成する出力は ±12 V に収める((3))。両者が衝突する場合は(3)を優先する。素通し・加算・追従系(アッテヌバータ、ミキサー、スルー)は**出力(または追従の目標値)を ±12 V でクランプ**する。[A]
6. **デバイス境界の例外**: 仮想の電圧(V)から実音声デバイスへの写像は、本書の対象ではなくIO仕様(MOD-IO-001)が定める(例: ±5 V = ±1.0 フルスケール)。この写像はCOM-02(1)の例外。[A]

## COM-03 ピッチ

- [R] 周波数制御は 1 V/oct。オシレータの基準はC4(261.6256 Hz)、LFO/クロックの基準は120 BPM(2 Hz)(F-005-013、F-001-005)。
- 周波数: `f = f0 · 2^V`。`f0` は音声VCOでは 261.6256 Hz(`pitch = 0 V` がC4)、LFO/クロックでは 2 Hz。[R]
- MIDIノート `n`(60=C4)との対応: `V = (n − 60) / 12`。[X]
- Hz/V方式との関係(参考): `V_hz = 2^(V_oct − 1)`(F-001-045、確度medium)。本製品は1 V/oct のみ。
- 資料により原機のピッチ規約は異なる(Buchla 1.2 V/oct 等。T-012のunconfirmed)。変換は後続の互換モジュールで扱う。[A]

## COM-04 ゲートとトリガー

**検出(入力側)**: シュミットトリガで二値化する。[R] F-005-011(低閾値≈0.1 V、高閾値≈1〜2 V)。[A] 本書は **ON閾値 = 2.0 V、OFF閾値 = 0.1 V** に固定する(Doepfer A-100は+3 V超をhigh: F-001-006。5 V/10 Vのゲートはどちらも2.0 Vを超えるため両立)。
```
state' = (state == 0 && v >= 2.0) ? 1
       : (state == 1 && v <= 0.1) ? 0
       : state
rising_edge = (state == 0 && state' == 1)
```
- **gate**: `state==1` の間が「アクティブ」。立ち上がりと立ち下がりの両方に意味がある。
- **trigger/clock**: `rising_edge` だけが意味を持つ。パルス幅は無視する。
- **同時**: 同一サンプルで複数入力が立ち上がった場合の処理順は各モジュール仕様が明記する(COM-07)。

**生成(出力側)**: [R] F-005-011。[A]
- gate high = 10 V、low = 0 V。
- trigger/clock パルス = 10 V、幅 `max(1, round(0.001 · fs))` サンプル(1 ms)。
- [R] 三角やノコギリなど立上りの遅い信号をトリガ入力に使うことは非推奨(F-001-008)。仕様上は入力値をそのまま閾値判定する。

- パルス幅の上限: 周期が短く `round(0.001·fs)` サンプルのパルスが周期の半分を超える場合は、`floor(周期/2)`(最小1サンプル)に切り詰めてよい。切り詰める仕様は §7 に例外として明記する。[A]

**未解決(#3判断)**: 実機のS-trig(GND短絡型)はモデル化しない。[A] F-001-051(確度medium)

## COM-05 時間と更新周期

- 全モジュールは**単一のサンプルレート `fs`** で同期して動作する。`fs` はエンジン設定(既定 48000 Hz。[A])で、起動後に変更する場合は全状態を再初期化する。
- **1サンプルを1ステップ**として、全モジュールが一斉に「入力を読む → 状態を更新 → 出力を書く」を行う。(ブロック処理は実装の自由だが、結果はこの1サンプル処理と一致しなければならない。[A])
- 音声レート信号(`audio`、`cv`)と制御レート信号(`gate`、`trigger`)を区別しない。全てサンプル毎。[A]
- パラメータはステップ開始時の値を使う。UI/エージェントからの変更は**次のステップ**から有効(COM-13)。
- サンプルレート依存: 時間パラメータ(秒)は `fs` に応じて係数を再計算する。各仕様に依存式を明記する。
- **内部状態の精度**: 時間を積分・累積する状態(位相アキュムレータ、タイマ、クロック位相)は**64bit倍精度**で保持する。float32では長時間に整数サンプル位置がずれ、COM-14のビット同一性が保証できないため。「時間の積分」には、エンベロープ・スルーなど**時間とともに一定量ずつ進む値**(Attackのランプ、線形スルー)も含める。上記以外の状態(フィルタ状態、遅延バッファの値等)の精度は各仕様が指定し、許容誤差の根拠にする。[A]

## COM-06 接続遅延とフィードバック

- [R] 各ケーブルは信号に**1サンプルの遅延**を与える(F-005-012)。
- 本書も同様とする。[A] 出力ポートの値は、そのステップで書かれた値が**次のステップ**に接続先の入力から見える。これにより評価順序に依存せず結果が決定し、フィードバックループも常に定義される。
- **モジュール内遅延**(ディレイの最小遅延、フィードバック段等)は、ケーブル遅延とは**別に加算**される。各仕様が内部遅延量を明記する。[A]
- したがって、モジュール単体の検証例は「入力列 `x[n]`(そのステップで入力ポートが読む値)→出力 `y[n]`(そのステップで書く値)」で記述する。ケーブル遅延はモジュール間接続でのみ現れる。

## COM-07 イベントの時刻と同時発生順序

- イベント(立ち上がり、リセット等)の時刻は**サンプル番号**。サブサンプル精度は持たない。[A]
- 同一ステップ内の処理順(モジュールが複数のイベント入力を持つ場合の既定順): **RESET → CLOCK/TRIGGER → GATE状態更新 → その他の連続値**。各仕様が例外を明記する。[A]
- [R] CLOCKとRESETを持つモジュールは、RESET後 **1 ms** の間CLOCKを無視すべき(F-005-012)。本書の対象モジュールは仕様ごとに採用の有無を明記する。無視区間は `ceil(0.001 · fs)` サンプル。RESETが**レベル型**(highの間リセット状態を保つ)の場合、無視区間は**RESETがlowに戻ったステップから**数える。[A]
- **丸めの区別**: 生成するパルス幅は `round(0.001·fs)`(COM-04)、無視区間は `ceil(0.001·fs)`(上記)で、意図的に異なる(例: fs=44100 で幅44、無視45)。[A]
- **旧状態の参照**: 同一ステップ内のイベント判定が別入力の状態(例: ADSRのRETRIGGERはGATE)に依存する場合は、**そのステップ開始時の状態**を使う。[A]
- **エッジ型RESET**(立ち上がりでリセットする入力)の無視区間(採用する場合)は、**立ち上がりを検出したステップ**から数える。[A]
- **MIDI等の外部イベント**: デバイス到着時刻→サンプル番号の割当は、エンジン/IO層(#3)が規定する。モジュール仕様は、割り当てられたサンプル内では**到着順**に処理する。[A]

## COM-08 ポリフォニー

- [R] ケーブルは最大16チャンネル(F-005-016/017)。単音は1チャンネルの特殊ケース(F-005-018)。
- 各ポートは `channels` を持つ(1〜16)。ポリフォニー対応モジュールは、主入力のチャンネル数 `N` で内部エンジン数を決め、各チャンネルを独立に処理する(F-005-019/020)。
- 副入力の扱い: 1チャンネルなら全エンジンへコピー、`N` チャンネルなら対応、不足分(範囲外チャンネル)は 0 V。[R]→[A]
- **加算系の例外**: 同等の入力を加算するモジュール(ミキサー)では「1チャンネルなら全エンジンへコピー」を適用せず、各入力の `ch` を独立に加算し、不足チャンネルは 0 V とする(単音入力は1チャンネル目だけに寄与)。コピー規則は設定値的な副入力(CV感度等)に適用する。[A]
- **初期版の方針**: 各モジュール仕様は**モノ(1チャンネル)の振る舞い**を正本とし、ポリフォニー時は「チャンネルごとに独立に同じ式を適用」とする。チャンネル間の相互作用を持つモジュールは各仕様に明記する。[A]

## COM-09 未接続と正規化(normalling)

- ポートは `connected` かどうかを持つ。入力が未接続のとき、各仕様の「未接続時」列の値を使う。**既定は 0 V**。[A](VCV Rackの各入力の未接続値は本調査未確認: 精査済みDB I003)
- **正規化**: 入力が未接続のとき別の信号(例: ノイズ、定数、別ポート)を代わりに使う設計は、各仕様の「未接続時」列に `normal=…` と明記する。接続すると正規化は切れる。[R] 例: M001(A-110-1)のCV1がバスCV正規化、I002のセミモジュラー内部接続。
- 出力は未接続でも通常どおり計算する。

## COM-10 初期化とリセット

- **リセットの種類**(各仕様は§5で、どれに当たるかを明記する)。[A]
  | 種類 | 内容 |
  |---|---|
  | 全体リセット `reset()` | 全内部状態を初期値へ。PRNG再シード |
  | 位相リセット(OSC `sync`、LFO `reset` 等) | 位相のみ0へ。出力イベントは出さない |
  | 音楽的リセット(CLK/SEQ/分周の `RESET` 等) | 位置・カウンタを先頭へ。発火の有無・出力の保持は各仕様が定める |
- 各モジュールは**初期状態**を持つ(各仕様 §5)。生成直後・`reset()` 直後・復元時の初期値がこれと一致する。[A]
- `reset()`(エンジン全体の初期化)は全内部状態を初期値へ戻す。パラメータ値は変えない。PRNGは再シードする(COM-11)。初期値がパラメータに依存する状態(例: 平滑化器の現在値)は、**リセット時点のパラメータ目標値**で初期化する。[A]
- モジュールが持つ **RESET入力ポート**(例: シーケンサのリセット)は、そのモジュールの音楽的リセットであり、`reset()` と異なる。各仕様が「何をリセットするか」を明記する。

## COM-11 乱数とシード

再現可能な乱数のため、アルゴリズムを固定する。[A]

**PRNG: xoshiro128\*\*(32bit)**、状態の初期化は SplitMix32 風の混合関数。全演算は uint32(mod 2³²)。
```
mix(x):                        // x は uint32 の変数。呼ぶたびに x を更新して返す
  x = x + 0x9E3779B9
  z = x
  z = (z ^ (z >> 16)) * 0x85EBCA6B
  z = (z ^ (z >> 13)) * 0xC2B2AE35
  return z ^ (z >> 16)

seed(s):  x = s;  s0 = mix(x);  s1 = mix(x);  s2 = mix(x);  s3 = mix(x)
next():   result = rotl(s1 * 5, 7) * 9
          t  = s1 << 9
          s2 = s2 ^ s0;  s3 = s3 ^ s1;  s1 = s1 ^ s2;  s0 = s0 ^ s3
          s2 = s2 ^ t;   s3 = rotl(s3, 11)
          return result                                   // uint32
uniform():  (next() >> 8) / 16777216.0                    // [0,1) の値(24bit精度)
```
**参照値**(この仕様の検証用スクリプトで算出した値。外部標準の値ではないが、実装者は同じ値になることを確認する):

| seed | 初期状態 (s0,s1,s2,s3) | next() ×3 |
|---|---|---|
| 0 | 92CA2F0E, 3CD6E3F3, 1B147DCC, 4C081DBF | E308DC58, 4392D0E4, 03318F97 |
| 1 | 96A0F96B, 12BC8390, 971E9964, 79ADC7E7 | 9190299E, C1017B27, E3AF522F |
| 12345 | 479199B4, 30C2CBD5, 3B5FD909, 8EE55794 | 1EEA3CC1, 1A40A62E, FC4CD240 |

seed=1 の `uniform()` ×3 = 0.5686059594, 0.7539288402, 0.8893939257(許容: 絶対 1e-9。値は 24bit整数÷2²⁴ で厳密)。
- **seedの正規化**: パラメータ値 `v` から `uint32` への変換は、NaN/∞→各仕様の既定seed、`v < 0` → 0、非整数は切り捨て、`≥ 2³²` は mod 2³²。[A]
- **相関への注意**: 既定seedが同じ複数のモジュールは同一の乱数列を出す。併用するときはseedを変えること(各仕様の既定は互いに異なるとは限らない)。
- シードは `uint32`。各乱数使用モジュールは自分の `seed` パラメータ(既定値は仕様で定める)と専用のPRNG状態を持つ。
- 保存・復元でPRNG状態(`s0..s3`)を含める(COM-14)。
- **seedの実行中変更**: `seed` はパラメータ変更として扱い、**次のステップで再シード**する(適用済みseedを内部状態 `applied_seed` として持つ)。復元時は保存されたPRNG状態を使い、再シードしない。[A]

## COM-12 異常入力と数値安定性

- [R] 有限入力でNaN/無限大を出しうるモジュールは **0 を返す**べき(F-005-014)。本書は全出力に適用する: 出力値が NaN または ±∞ なら 0 を書く(内部状態も 0 に戻すかは各仕様)。[A]
- 非正規化数(denormal)は 0 に丸めてよい(実装自由)。結果の許容誤差に影響しないよう、検証例の許容誤差は 1e-6(絶対)以上とする。
- 周波数・時間パラメータの範囲外値は、仕様の範囲へクランプする(各仕様 §4 に明記)。
- 入力のNaN/∞は、内部で 0 V として扱う。[A]
- **パラメータ**が NaN/∞ のときは**既定値**として扱う。有限の範囲外値は仕様の範囲にクランプする(COM-13)。両者を区別する。[A]
- NaN/∞→0 の置換は不具合を隠しうる。診断用の非有限値カウンタ(例: MOD-IO-003 の `nonfinite_count`)の提供は任意だが、提供するモジュールはCOM-12の置換を行った回数を数える。[A]

## COM-13 パラメータ

各パラメータは `名前・単位・範囲・既定値・変調可否・更新タイミング・補間` を持つ(各仕様 §4)。
- **更新タイミング**: 既定は「次のステップ」。補間(スムージング)がある場合は時定数を明記する。補間なしのパラメータは階段状に変化する。
- **変調可能**: CV入力ポートを持つパラメータは、`有効値 = clamp(param + k · cv_in)` の形で、`k`(感度)と clamp 範囲を明記する。
- **補間の既定**: 補間なし(階段状に変化)。クリックやジッパーノイズが問題になるパラメータは、各仕様が時定数を明記して平滑化する。[A]
- **整数型パラメータ**(ステップ数、分周比、PPQN等)は、**最近接整数へ四捨五入(0.5は切り上げ)した後**に範囲へクランプする。NaN/∞は既定値(COM-12)。[A] 例外: 乱数のseed(COM-11)は切り捨て。**列挙型**パラメータ(モード選択等)も整数型として扱い、四捨五入→クランプする。[A]
- 範囲外のパラメータ設定はクランプする(エラーにはしない)。外部操作インターフェース(#3)での検証エラーは別層。

## COM-14 状態保存・復元・版互換

- 保存対象: ①パラメータ値、②内部状態(各仕様 §5 の全変数)、③PRNG状態、④モジュール種別ID(`spec_id`)と**仕様版**。
- **復元後の同値性**: 保存直後の状態から復元したモジュールは、同じ入力列に対し、保存しなかった場合と**ビット同一**の出力列を返さなければならない(§10 の「復元」検証例)。[A]
- 仕様版が上がっても、保存データの意味を保つ。互換が壊れる場合は旧版からの移行規則を各仕様 §9 に書く。
- 保存形式(JSON等)はこの仕様の対象外(#3のデータ契約)。ここでは**何を保存するか**だけを定める。

## COM-15 検証例(テストベクトル)の書式

各仕様 §10 に検証例を表で書く。列:

| TV-ID | 種別 | 前提 | 入力 | 期待値 | 許容誤差と根拠 |
|---|---|---|---|---|---|

- **種別**: `正常` / `境界` / `無効入力` / `未接続` / `リセット` / `保存復元`。該当しない種別は理由を書く。
- **前提**: `fs`、パラメータ値、初期状態。省略値はCOM-05(fs=48000)と各仕様 §4 の既定値。
- **入力**: ステップ番号 `n=0,1,…` と値。長い列は式で書く(例: `x[n]=sin(2π·1000·n/fs)`)。
- **期待値**: 式、または数値。**手計算または検証用スクリプトで確認した値**を書く(推測値を書かない)。
- **許容誤差**: 絶対誤差または相対誤差と、その根拠(浮動小数点精度、フィルタの近似式の許容など)。音響特性の検証(周波数応答、スペクトル)は、測定方法(窓、区間)と許容を明記する。
- **許容誤差**は絶対誤差と相対誤差の併用を許可する(`|y − expected| ≤ max(abs, rel·|expected|)`)。値の小さい波形に絶対 1e-6 は緩すぎるため。根拠(float32丸め、近似式の限界等)を必ず書く。
- **種別セル**は完全一致(`正常`/`境界`/`無効入力`/`未接続`/`リセット`/`保存復元`)。補足は前提列に書く(検査ツールは種別セルを完全一致で見る)。
- 機能再現と音質を混同しない。音質(スペクトルの滑らかさ、エイリアシング)の要件は別項に分ける。

## COM-16 仕様の追跡

- 各モジュール仕様のフロントマターに `refs`(リファレンスID)を列挙し、§2 の表で[R]/[A]/[X]ごとに対応づける。
- 仕様IDは `MOD-<分類>-<3桁>`(例: `MOD-OSC-001`)。重複・参照切れは `tools/validate_specs.py` が検査する。
- [R] を主張する記述は必ずリファレンスIDを持つ。IDを持たない記述は[A]または[X]。

## COM-17 時間の定義(指数・線形)

- 資料は時間パラメータの定義を与えない(M002等)。本書は次のとおり固定する。[A]
- **線形区間の時間 `T`**: 始点から終点まで直線で進むのに要する時間。
- **指数区間の時間 `T`**: 残差が初期値の **1/1000(−60 dB)** になるまでの時間。一次系の時定数は `τ = T / ln(1000)`。1サンプルの係数は `a = exp(−1/(τ·fs))`。
- 「時定数 τ」と明記したパラメータ(例: 平滑化)は上記と区別し、そのまま `τ` として使う。
- 終端スナップ(十分近い値で目標値に一致させる)の閾値は各仕様が定める。閾値を**満値基準の絶対値**で定める仕様では、`T` は満値からの遷移でのみ厳密で、部分的な遷移では `T` より早く終わる。各仕様はこの性質を明記する。[A]

## COM-18 CV感度の形

CVでパラメータを変調するときは、仕様ごとに次のどちらかの形で書き、感度 `k`(名前と単位)を§4に明記する。[A]
| 形 | 式 | 例 |
|---|---|---|
| 加算型 | `eff = clamp(param + k·cv)` | 遅延時間、利得、レゾナンス |
| 指数型(oct/V) | `eff = param · 2^(k·cv)` | 周波数、カットオフ、BPM |
名前の規則(推奨): 感度は `<対象>_amt` または `<対象>_cv`、CV入力の減衰器は `cv<n>_level`。ポート名の大文字・小文字は仕様内で一貫していればよい(トリガ/ゲート入力は大文字が多い)。同名パラメータ(`gain`、`level`)の意味(倍率かVか)は各仕様が明記する。

**ピッチの特別な形**: 1 V/oct の `pitch` 入力と `range`/`tune`(V換算の加算量)は、先に**電圧領域で加算**してから周波数へ変換する(`V = pitch + range + tune + k·fm`、`f = f0 · 2^V`、COM-03)。これは指数型の一例で、`param` に当たるのは `f0·2^(range+tune)`、`k` は `fm` の oct/V である。各仕様が採る式を§6に書く。
