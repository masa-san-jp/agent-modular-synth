# MOD-ENV-001 ADSRエンベロープ

## 1. 目的と範囲
- 目的: GATE入力の立ち上がりでAttack(線形上昇)→Decay(指数減衰)→Sustain(保持)へ進み、GATEの立ち下がりでRelease(指数減衰)へ移る単極の制御電圧 `env`(0〜10 V)と、その反転 `inv` を毎サンプル出力する。RETRIG入力でGATE保持中にAttackへ戻せる。
- 含む: A/D/S/Rの4パラメータ、GATE、RETRIG、正出力と反転出力、リセット、状態保存。
- 含まない: 時間のCV変調、ステージ別の曲線形状切替、ループ(サイクル)動作、Hold段、時間範囲の3段スイッチ(原機M002の L/M/H)。これらは後続または#3で追加する(§11)。

## 3. ポート
| 名前 | 方向 | 型 | ch | 単位 | 範囲 | 更新周期 | 未接続時 |
|---|---|---|---|---|---|---|---|
| gate | in | gate | 1 | V | 任意の有限値(シュミット: ON 2.0 V以上、OFF 0.1 V以下) | サンプル毎 | 0 V(常にlow。エンベロープは起動しない) |
| retrig | in | trigger | 1 | V | 任意の有限値(立ち上がりのみ有効) | サンプル毎 | 0 V(イベントなし) |
| env | out | cv | 1 | V | 0〜10(常に範囲内) | サンプル毎 | 出力は未接続でも計算する |

ポリフォニー(COM-08): モノを正本とする。`gate` のチャンネル数 `N` で内部エンジン数を決め、各チャンネルを独立に処理する。`retrig` が1チャンネルなら全エンジンへコピー、`N` チャンネルなら対応、範囲外は0 V。

## 4. パラメータ
| 名前 | 単位 | 範囲 | 既定値 | 変調 | 更新タイミング | 補間 |
|---|---|---|---|---|---|---|
| attack | 秒(0 V→10 Vの時間) | 0.001〜60(範囲外はクランプ) | 0.01 | なし(CV入力ポートを持たない。時間CVは後続: §11) | 次のステップ | なし(レートは毎ステップ現在値から計算) |
| decay | 秒(距離が1/1000になる時間) | 0.001〜60(クランプ) | 0.1 | なし | 次のステップ | なし |
| sustain | 無次元(倍率。env=10·sustain V の比であり電圧ではない) | 0〜1(クランプ) | 0.5 | なし | 次のステップ(Sustain段中は `x` が即座に追従し階段状に変化) | なし |
| release | 秒(距離が1/1000になる時間) | 0.001〜60(クランプ) | 0.1 | なし | 次のステップ | なし |

- **NaN/∞のパラメータ値は既定値**(attack=0.01, decay=0.1, sustain=0.5, release=0.1)として扱う(COM-12)。有限の範囲外値は範囲へクランプする(COM-13)。例: `sustain=+∞` は 0.5(1にクランプではない)、`attack=−1` は 0.001。
- CV感度(COM-18): 本モジュールはパラメータを変調するCV入力を持たない(感度 `k` なし)。
- 時間の定義(COM-17): `attack` は線形区間(0→満値の所要時間)。`decay`/`release` は指数区間の時間 `T`(残差1/1000になる時間、時定数 `τ = T/ln1000`)だが、スナップ閾値が満値基準の絶対値(0.001、10 mV)のため、実際の所要時間は遷移の大きさで変わる。Decayは `D·log₁₀₀₀((1−S)/0.001)`(`S=0` で `D`、`S=0.5` で約 0.8997·D、`S=0.8` で約 0.767·D、`1−S ≤ 0.001` では1ステップ)、Releaseは出発値 `x₀` から `R·log₁₀₀₀(x₀/0.001)`(満値から `R`、`S=0.5` のSustainから約 0.8997·R)。ステップ数は切り上げ。

## 5. 内部状態と初期化・リセット
- 状態変数:
  - `x`: 実数(正規化レベル 0〜1)、初期値 0。**64bit倍精度**で保持する(COM-05: Attackのランプ `x += rate` は時間とともに一定量ずつ進む状態であり、指数区間の `x` も同様。float32では累積でステップ数がずれうる)。出力 `env`, `inv` はポート値(32bit浮動小数点, COM-02)へ書くときに丸める。
  - `stage`: 列挙 {IDLE=0, ATT=1, DEC=2, SUS=3, REL=4}、初期値 IDLE。
  - `g`: GATE用シュミット状態 {0,1}、初期値 0。
  - `r`: RETRIG用シュミット状態 {0,1}、初期値 0。
- `reset()`: `x=0, stage=IDLE, g=0, r=0`。パラメータは変えない。乱数は使わない。リセット時点でGATEが入力でhighのままの場合、次のステップで立ち上がりとみなして再起動する(`g=0` のため)。
- RESET入力ポート: 持たない(ADSRに音楽的リセットはない)。

## 6. 振る舞い
1ステップ(サンプル)の処理。`fs` はエンジンのサンプルレート(COM-05)。入力値のNaN/∞は0 Vとして扱い、パラメータのNaN/∞は既定値とする(COM-12)。`x` は倍精度で計算する。
```
// パラメータ(NaN/∞は既定値、その後クランプ)
A = clamp(finite_or(attack, 0.01), 0.001, 60);   D = clamp(finite_or(decay, 0.1), 0.001, 60)
R = clamp(finite_or(release, 0.1), 0.001, 60);   S = clamp(finite_or(sustain, 0.5), 0, 1)

// 1. 入力の読み取りとシュミット検出(COM-04: ON>=2.0, OFF<=0.1)
g_prev = g                            // このステップ開始時のGATE状態
(r_prev, r) = schmitt(retrig, r);   redge = (r_prev==0 && r==1)
(g_prev2, g) = schmitt(gate,  g);   gup = (g_prev==0 && g==1);  gdn = (g_prev==1 && g==0)

// 2. イベント(COM-07: RETRIG → GATE の順)
if redge && g_prev==1:  stage = ATT          // 旧GATE状態がhighのときだけ有効
if gup:                 stage = ATT
if gdn && stage != IDLE: stage = REL

// 3. 時間進行(現在の stage を1サンプル進める。ATT/DEC/RELは同じステップ内で進む)
switch stage:
  ATT: rate = 1/(A*fs);  x = x + rate
       if x >= 1 - rate/2:  x = 1;  stage = DEC          // 次のステップからDEC
  DEC: kd = exp(-ln(1000)/(D*fs));  x = S + (x - S)*kd
       if x - S <= 0.001:   x = S;  stage = SUS
  SUS: x = S                                             // sustain変更に即追従
  REL: kr = exp(-ln(1000)/(R*fs));  x = x*kr
       if x <= 0.001:       x = 0;  stage = IDLE
  IDLE: 何もしない

// 4. 出力
env = 10*x;   inv = (env==0) ? 0 : -env
```
- サンプルレート依存: Attackの1ステップ増分は `1/(A·fs)`、Decay/Releaseの係数は `exp(−ln1000/(T·fs))`(T=D または R)。同じ秒数なら `fs` によらず時間が一致する。ステップ数が整数でない場合の終了ステップは最大±1サンプル(切り上げ)ずれる。
- Attack終了判定 `x >= 1 − rate/2` は、増分の累積誤差でステップ数が変わらないための丸め規則である。倍精度でも `A·fs` ステップの加算で `x` は1に対し約1e-13ずれ、`x >= 1` では1ステップ遅れうるため、増分の半分の余裕を持たせる。
- ATT終了ステップでは `x=1` を出力し(`env=10`)、`stage` はDECになるが減衰は次のステップから始まる。
- 同一ステップでGATE立ち上がりとRETRIG立ち上がりが重なっても、Attack開始は1回(`stage=ATT`)で、結果は同じ。
- GATE立ち下がりとRETRIG立ち上がりが同じステップに重なった場合(旧GATE=high)、RETRIGでATTにした後にGATE立ち下がりでRELへ移る。結果はRelease(検証例TV-MOD-ENV-001-08)。
- RELの途中でGATEが再び立ち上がると、現在値からAttackを再開する(TV-MOD-ENV-001-06)。
- **終端スナップと時間 `T`(COM-17)**: Decay/Releaseのスナップ閾値は満値基準の絶対値(`x − S ≤ 0.001`、`x ≤ 0.001`、満値の0.1%)である。そのため `T` どおりに終わるのは満値(`x−S=1`、`x=1`)からの遷移だけで、部分的な遷移は `T` より早く終わる。Decayの所要は `D·log₁₀₀₀((1−S)/0.001)`(`S=0.5` で約0.8997·D。既定値では 4319 ステップ、`D·fs=4800` の約0.9倍。TV-01 の Sustain 開始 n=4798、TV-19)、Releaseは出発値 `x₀` から `R·log₁₀₀₀(x₀/0.001)`(`S=0.5` から4319ステップ、TV-01 の n=27318)。閾値(0.001)自体は変えない。
- Decayの途中でSが現在値より大きくなった場合(`x − S` が負)、直ちに `x=S` へスナップする。
- 出力の書き込みは当該ステップ末で、次のステップに接続先の入力から見える(COM-06)。

## 7. 共通規約との関係
- COM-04: GATE/RETRIGのシュミット閾値は ON 2.0 V、OFF 0.1 V。RETRIGはtrigger扱い(立ち上がりのみ)。
- COM-05/06: 1サンプル処理。出力は次ステップで接続先が読む。
- COM-07: 同一ステップの順序は RETRIG → GATE。COM-07の「RESET後1 msはCLOCKを無視」は、RESET/CLOCK入力を持たないため該当しない。
- COM-02: 出力は0〜10 Vと−10〜0 Vで、±12 Vを超えない(クリップ不要)。
- COM-12: 出力がNaN/∞になる経路はない。入力のNaN/∞は0 V、**パラメータのNaN/∞は既定値**(§4)、有限の範囲外パラメータはクランプ(COM-13)。
- COM-13: パラメータ変更は次のステップから有効。補間なし。
- COM-17: `attack` は線形区間、`decay`/`release` は指数区間の時間。ただし終端スナップが満値基準の絶対値のため、部分遷移では `T` より短い(§4, §6)。
- COM-18: CV入力を持たないため感度 `k` の対象外(§4)。
- COM-05: `x`(Attackのランプと指数の状態)は64bit倍精度(§5)。
- 例外: 本モジュールは「RETRIGがGATEの旧状態に依存する」点が、COM-07の既定順に対する固有の規則である。

## 8. 異常入力・境界・数値安定性
- NaN/±∞のGATE/RETRIG入力は0 Vとして扱う(TV-09, TV-11)。
- GATEが2.0 V未満の三角波などは起動しない。ちょうど2.0 Vで起動する(TV-09)。
- 範囲外(有限)パラメータはクランプ。`attack=0` → 0.001、`sustain=1.5` → 1(TV-10)。NaN/∞のパラメータは既定値(`attack`/`decay`/`release`/`sustain` = 0.01/0.1/0.1/0.5)で、クランプ値ではない(TV-18)。
- `S=1` ではDecayが即座に終わる(TV-04)。`S=0` ではDecay後に0でSustainする(TV-05。この満値からの遷移で所要が `D` と一致する)。`1−S` が0.001以下でも1ステップで終わる。部分遷移は `T` より早く終わる(§6、TV-01, TV-19)。
- 出力は常に有限で `0 <= env <= 10`。長時間のIDLEで `x` はちょうど0(スナップ)。非正規化数は発生しない。`x` は倍精度のため長時間でもAttackのステップ数はずれない。
- 音質(クリックの有無など)は本仕様の対象外。機能再現(時間的な挙動)のみを検証する。必要なら別項で「Attack開始・終了時の不連続の大きさ」を測る(§11)。

## 9. 保存・復元・版互換
- 保存対象: パラメータ4つ(attack, decay, sustain, release)、内部状態(`x`, `stage`, `g`, `r`)、`spec_id=MOD-ENV-001` と仕様版 `0.1`。乱数は使わないためPRNG状態はない。
- 復元の同値性: 保存直後の状態から復元したモジュールは、同じ入力列に対しビット同一の出力列を返す(TV-17)。`x` は保存時の精度のまま保存する。
- 版移行: 初版のため旧版はない。曲線式を変える場合は新しい仕様版とし、旧保存データの `x` の意味(正規化レベル 0〜1)は保つ。
