# MOD-FNC-001 スルー/関数発生器

## 1. 目的と範囲
- 目的: 1チャンネル分の関数発生器。(a)入力 `in` に出力 `out` が上昇側時間 `rise`・下降側時間 `fall` で追従する(スルー/ラグ/ポルタメント)、(b)`trig` の立ち上がりで 0→10 V→0 のトランジェント関数を生成する(エンベロープ)、(c)`cycle` がhighの間は(b)を繰り返す(LFO)。関数の区間終了を `eor`(End of Rise)・`eoc`(End of Cycle)で出力する。
- 含む: rise/fall時間、線形/指数の応答選択、rise/fall時間のCV変調、trig/cycle、eor/eoc、リセット、保存。
- 含まない: Mathsの4チャンネル構成、SUM/ORバス、Both CV(rise/fall同時変調)、対数応答と連続可変のVari-Response、ゲート遅延、gate↔アナログ変換、Unity出力、チャンネル間リンク(F-002-003にあるその他の機能)。§11に列挙。

## 4. パラメータ
| 名前 | 単位 | 範囲 | 既定値 | 変調 | 更新タイミング | 補間 |
|---|---|---|---|---|---|---|
| rise | 秒(線形: 10 Vの移動時間、指数: 10 Vの遷移で残差1/1000になる時間。部分遷移は §6) | 0.001〜100(クランプ) | 0.1 | rise_cv: `T_eff = clamp(rise·max(0,1+cv/8), 0.001, 100)` | 次のステップ | なし(速度は毎ステップ現在値から計算) |
| fall | 秒(同上) | 0.001〜100(クランプ) | 0.1 | fall_cv: `T_eff = clamp(fall·max(0,1+cv/8), 0.001, 100)` | 次のステップ | なし |
| response | 列挙(0=線形, 1=指数) | 0 または 1(0.5以上を1、未満を0に丸める) | 0 | なし | 次のステップ | なし(切替で状態 `y` は連続) |

- **NaN/∞のパラメータは既定値**(rise=fall=0.1, response=0)として扱う(COM-12)。有限の範囲外値はクランプ(COM-13)。例: `rise=+∞` は 0.1(100 sにクランプではない)。
- **CV感度の形(COM-18)**: rise_cv/fall_cv は、時間 `T` に比例する**相対加算型** `T_eff = clamp(T·max(0, 1 + k·cv))`。`k = 1/8 V⁻¹` は**固定値**でパラメータにしない(S-13)。COM-18 の加算型(`param + k·cv`、k は秒/V)でも指数型(oct/V)でもなく、感度が `T` に比例する形である(§11)。
- **時間の定義(COM-17)**: 線形は `rise`/`fall`=10 Vの移動時間(ΔV の移動は `T·ΔV/10`)。指数は10 Vの遷移で残差1/1000(`τ = T/ln1000`)だが、スナップ閾値が満値(10 V)基準の絶対値(10 mV)のため、距離 `d0` の遷移の所要は `T·log₁₀₀₀(d0/0.01)`(切り上げ)。`d0=10` で `T`、`d0=5` で約0.9·T、`d0=12` で約1.026·T。
- 単位: `rise`/`fall` は秒、`response` は列挙(倍率やVではない)。出力のスケールは固定(関数は0〜10 V)で利得パラメータはない。

## 5. 内部状態と初期化・リセット
- 状態変数: `y`: 実数(V)、初期値0。**64bit倍精度**で保持する(COM-05: 線形スルーの `y += st` は時間とともに一定量ずつ進む状態であり、指数の `y` も同様)。出力 `out` はポート値(32bit)へ書くときに丸める。`stage`: 列挙 {IDLE=0, RISE=1, FALL=2}、初期値IDLE。`t`: trigのシュミット状態、初期値0。`c`: cycleのシュミット状態、初期値0。
- `reset()`: `y=0, stage=IDLE, t=0, c=0`。パラメータは変えない。
- RESET入力ポート: 持たない。

## 6. 振る舞い
1ステップの処理。入力のNaN/∞は0 V、パラメータのNaN/∞は既定値として扱う(COM-12)。`fs` はサンプルレート。`y` は倍精度で計算する。
```
inp = clamp(in, -12, 12)
// パラメータ: NaN/∞は既定値(rise=fall=0.1, response=0)、その後クランプ。response は 0.5以上を1、未満を0
Tr = clamp( clamp(finite_or(rise,0.1),0.001,100) * max(0, 1 + rise_cv/8), 0.001, 100 )
Tf = clamp( clamp(finite_or(fall,0.1),0.001,100) * max(0, 1 + fall_cv/8), 0.001, 100 )
nr = max(1, Tr*fs);  nf = max(1, Tf*fs)             // ステップ数
(t_prev, t) = schmitt(trig,  t);  (c_prev, c) = schmitt(cycle, c)

// 1. イベント(COM-07: TRIGGER → GATE(cycle) の順)
if (t_prev==0 && t==1) && stage != RISE:  stage = RISE   // 上昇中のtrigは無視、下降中は現在値から再上昇(S-06)
if c==1 && stage == IDLE:                 stage = RISE

// 2. 移動 move(y, target, n) -> (y', done)
//    線形:  st = 10/n
//           if |target-y| <= 1.5*st:  return (target, true)
//           return (y + sign(target-y)*st, false)
//    指数:  k = 1 - exp(-ln(1000)/n)
//           y' = y + (target - y)*k
//           if |target - y'| <= 0.01: return (target, true)
//           return (y', false)
if stage == RISE:  (y, done) = move(y, 10, nr);  if done: stage = FALL
elif stage == FALL:(y, done) = move(y, 0,  nf);  if done: stage = (c==1) ? RISE : IDLE
else:              n = (inp > y) ? nr : nf;  (y, _) = move(y, inp, n)   // スルー

// 3. 出力
out = y
eor = (stage == FALL) ? 10 : 0
eoc = (stage == RISE) ? 0 : 10
```
- サンプルレート依存: 線形は1ステップ `10/(T·fs)` V、指数は係数 `1−exp(−ln1000/(T·fs))`。同じ秒数なら `fs` によらず時間が一致する。
- 線形の終了判定 `|target−y| <= 1.5·st` は、増分の累積誤差でステップ数が変わらないための丸め規則(倍精度でも `n` ステップの加算で `y` は約1e-13ずれるため、増分の半分の余裕を持たせる)。
- RISEが完了したステップで `y=10` を出力し、`stage=FALL` になる(`eor` はそのステップから10 V)。FALLが完了したステップで `y=0` を出力する。`cycle` がhighなら `stage=RISE` となり `eoc` は0 V、そうでなければIDLEで `eoc` は10 V。
- 関数(RISE/FALL)の間は `in` を無視する。IDLEに戻ると `y` は0から出発して `in` へスルーする。
- 指数のスルーで `|in − y| <= 0.01 V` の場合は即座に `in` へスナップする(10 mV未満の変化は追従時間なし)。
- **終端スナップと時間 `T`(COM-17)**: 指数のスナップ閾値は満値(10 V)基準の絶対値(0.01 V)である。そのため所要時間が `T` と一致するのは10 Vの遷移(関数の 0↔10 V、10 Vのスルー)だけである。距離 `d0` の遷移の所要は `T·log₁₀₀₀(d0/0.01)`(切り上げ): 部分遷移はスナップが早く `T` より短く(`d0=5 V` で432ステップ=0.9·`T·fs`、TV-11)、`d0>10 V`(例: 0→12 V、−12→12 V)では `T` より長い(12 Vで493ステップ)。閾値自体は変えない。線形は `T·ΔV/10` で、`T` の定義(10 Vの移動時間)と矛盾しない。
- 出力の書き込みは当該ステップ末で、次のステップに接続先から見える(COM-06)。

## 7. 共通規約との関係
- COM-04: trig/cycleのシュミット閾値(ON 2.0 V, OFF 0.1 V)。trigは立ち上がりのみ、cycleはレベル。
- COM-05/06: 1サンプル処理、出力は次ステップで接続先が読む。
- COM-07: 同一ステップの順序は TRIGGER → cycle(gate状態)→ 連続値。COM-07の「RESET後1 ms無視」はRESET/CLOCK入力がないため該当しない。
- COM-02: 出力は `out` が ±12 V以内(入力を±12 Vにクランプ)、関数は0〜10 V。
- COM-09: 未接続は全入力0 V。
- COM-12: 出力がNaN/∞になる経路はない。
- COM-13: rise/fallのCV感度 `k=1/8 V⁻¹`、clamp 0.001〜100 s。パラメータのNaN/∞は既定値(COM-12)、有限の範囲外はクランプ。
- COM-17: 線形は10 Vの移動時間、指数は10 Vの遷移で残差1/1000。スナップ閾値が10 V基準の絶対値のため、部分遷移は `T` より短い(§4, §6)。
- COM-18: CV感度は相対加算型 `T·max(0,1+k·cv)`、`k=1/8 V⁻¹` 固定(§4)。
- COM-05: `y`(線形スルー・指数の状態)は64bit倍精度。

## 8. 異常入力・境界・数値安定性
- `in` のNaN/∞は0 V、範囲外(±12 V超)はクランプされた目標へ収束する(TV-07)。
- `trig` のNaN、`cycle` の∞は0 V扱いで関数は起動しない(TV-07)。
- `rise=0` は0.001 sにクランプ、`rise=1e9` は100 sにクランプ(有限の範囲外)。`response=0.7` は1(指数)。`rise`/`fall`/`response` が NaN/∞ のときは既定値(0.1/0.1/0)で、100 sへのクランプではない(TV-07(g)(h))。
- `rise_cv=−8` 以下では時間係数が0以下となり、`T_eff` は下限0.001 sにクランプされる(TV-06)。
- 時間が1サンプル未満(`T·fs<1`)の場合は `n=1`(1ステップで到達)。
- 出力は常に有限。長時間のIDLEで `y` は目標へスナップするため非正規化数は発生しない。
- 音質(スルー時の追従の滑らかさなど)は本仕様の対象外。機能再現(時間的挙動)のみを検証する。

## 9. 保存・復元・版互換
- 保存対象: パラメータ3つ(rise, fall, response)、内部状態(`y`, `stage`, `t`, `c`)、`spec_id=MOD-FNC-001` と仕様版 `0.1`。乱数は使わない。
- 復元の同値性: 保存直後の状態から復元したモジュールは、同じ入力列に対しビット同一の出力列を返す(TV-10)。
- 版移行: 初版のため旧版はない。応答の種類(対数など)を増やす場合は `response` の列挙値を追加し、既存値の意味を変えない。

## 11. 未確認・保留事項
- Mathsの信号タイミング(EOR/EOCの正確な立ち上がり・立ち下がり位置、トリガ中の入力取り扱い、Signal入力と関数の合成)は資料に詳細がない。S-11は[A]で、#3で原機の挙動を再確認するか判断する。
- 対数応答・連続可変のVari-Response(S-07)、Both CV、Unity出力、ゲート遅延、gate↔アナログ変換、SUM/ORバスは本仕様に含めていない。後続仕様で追加する。
- COM-18 の2形(加算型・指数型)のどちらにも当たらない相対加算型 `T·max(0,1+k·cv)` を採用している。共通規約に「相対加算型」を加えるか、本仕様を加算型(`T + k·cv`、秒/V)へ寄せるかは#3の判断。
- 指数応答の終端スナップを残差比(距離の1/1000)に変えるとCOM-17と厳密に一致するが、終了ステップが変わるため検証例を更新する。
- 時間の絶対値の正確さ(原機の25分〜1 kHz相当のレンジ、実際のRC時定数)は資料から決められない。範囲 0.001〜100 s は[A]で、レンジ拡張は#3の判断。
- 関数が走っている間の `in` の扱い(無視)は[A]。原機はIN信号が関数と混ざる経路があるが資料が詳細を述べない。
- `eoc` を「上昇段のみ0 V」と定義したため、cycle中は `eor` と同一波形になる。原機との差の評価は#3。
